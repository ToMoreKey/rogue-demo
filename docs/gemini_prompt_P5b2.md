### 1. ゴール
無限回廊「天蓋の塔」の最高到達階を、(1) 同意したプレイヤーだけ自動でフォームに送信し、(2) `data/ranking.json` の上位20位をゲーム内で表示する。取得に失敗してもゲームは壊れない（オフライン可）。

### 2. やること

#### 2-1. 設定（`src/data/ranking.js`、新規）
```
const RANKING_CFG = {
  formUrl: '',        // 例: 'https://docs.google.com/forms/d/e/XXXX/formResponse'（運営者が作成後に Claude が入れる）
  entryName: '',      // 例: 'entry.1111111'
  entryFloor: '',     // 例: 'entry.2222222'
  rankingUrl: 'data/ranking.json',   // ゲームと同じ場所からの相対パス
  top: 20,
  nameMax: 12,
  maxFloor: 500,
  cacheKey: 'rogue_ranking_cache_v1'
};
```
- `formUrl` などが空のとき（未設定）は、「送信」機能を無効にして、「ランキング送信は準備中です」と表示する（送信ボタンは押せない）。表示（読み込み）は動く。
- 設定を足すだけで、ゲーム側のコード変更なしに有効にできる構造にする。

#### 2-2. 表示（ランキング画面）
- 「天蓋の塔」カードに「ランキング」ボタンを追加し、モーダルを開く。内容:
  - 見出し「天蓋の塔 ランキング（更新: ○○）」（`updated` の日付。空なら「準備中」）。
  - 上位20位の表: 順位・ニックネーム・到達階。1〜3位は目立たせる（色・アイコン。画像は新規に作らない）。
  - 自分の記録: 「あなたの最高到達階: N階（ランキング換算: ○位相当／圏外）」。`p.tower.best` と、読み込んだランキングを比較して計算する。
  - ニックネームは必ずエスケープして表示する（`textContent` を使う。HTML注入をしない）。
- 取得: `fetch(RANKING_CFG.rankingUrl, {cache:'no-cache'})`。成功したら `localStorage`（キーは `cacheKey`）に保存する。失敗（オフライン、`file://` で開いた、404、JSON不正）したら、キャッシュを表示し、「オフライン（前回取得分を表示）」と出す。キャッシュも無ければ「ランキングを取得できません」。
- 読み込んだJSONは検証する（`entries` が配列、各要素の `name` が文字列で12文字以内、`floor` が1〜500の整数）。不正な要素は無視する。
- `localStorage` の読み書きは `try/catch`。ストレージが使えなくても動く。
- **サービスワーカー**: `sw.js` が `data/ranking.json` を**ネットワーク優先**（失敗時のみキャッシュ）で取得するようにする。ランキングが古いまま固定されないこと。ゲーム本体の既存のキャッシュの仕組みは壊さない。

#### 2-3. 送信（同意・ニックネーム・自動送信）
- 「ランキング」モーダルに「記録を送信する設定」を置く（`formUrl` 未設定のときは無効）:
  - ニックネームの入力欄（1〜12文字）。保存して有効にするボタン。
  - 同意の文言（チェック必須）: 「ニックネームと最高到達階が、ランキング用に送信されます（個人情報は送信しません）。送信した内容は運営者の確認後にランキングへ掲載されます。」
  - 設定の解除ボタン（以後は送信しない）。
  - 現在の状態の表示（送信する／しない、ニックネーム、最後に送信した最高階）。
- **自動送信**: 同意済みで、回廊のランが終わって `p.tower.best` が更新され、かつ `best > p.tower.sentBest` のときだけ、結果画面の表示と同時に送信する。1回の更新につき1回だけ送る（連打・再送信なし）。短時間に何度も送らない（同じ最高階を二度送らない。ランごとに最大1回）。
- 送信方法: `fetch(formUrl, {method:'POST', mode:'no-cors', headers:{'Content-Type':'application/x-www-form-urlencoded'}, body: new URLSearchParams({[entryName]: name, [entryFloor]: String(best)})})`。`no-cors` なので成否は分からない。送信後は「記録を送信しました（ランキングへの反映には時間がかかります）」と表示し、`sentBest` を更新する。例外・オフラインのときは「送信できませんでした」と表示し、`sentBest` を更新しない（次回の更新時に再送する）。
- 送信前の検証: ニックネームを前後の空白除去、制御文字除去、12文字以内、空でない。到達階は1〜500の整数。URLらしい文字列（`http`、`www.`、`@`）を含むニックネームは、その場で拒否してメッセージを出す。
- 手動送信ボタン（「今の最高記録を送信」）も置く。ただし、同じ最高階は、すでに送信済みなら押せない。

#### 2-4. セーブ
- `p.tower` に、`nick`（文字列）、`rankOptIn`（真偽）、`sentBest`（数値）を**追加するだけ**にする。既存セーブ（v1〜v5）に、これらが無くても動く（読み込み時に既定値を補う。バージョンを上げるなら `migrations` に追加し、テストを更新する）。バックアップの仕組みはこれまでと同じ。
- ニックネームや同意の状態を、他のフィールドに混ぜない。

#### 2-5. テスト（`tools/test_p5b2.py` を追加し、`README.md` に実行方法を書く）
- ランキングの表示: 正常な `ranking.json`（モック。`page.route` で返す）で、上位20位が正しく並ぶ。25件あっても20件だけ。自分の記録の順位換算が正しい（圏外・同順位を含む）。
- 検証: 不正なJSON、`floor` が範囲外・文字列、`name` が13文字以上の要素が無視される。HTMLを含むニックネーム（`<img onerror=...>`）が実行されず、文字として表示される。
- オフライン・失敗: `fetch` が失敗したとき、キャッシュを表示する／キャッシュがないときはメッセージを出す。ページエラーが出ない。
- 送信: `formUrl` 未設定のときは送信が無効。設定ありのとき、同意＋ニックネーム設定後に回廊のランが終わると、`page.route` でフォームへの POST が**1回だけ**発生し、本文にニックネームと到達階が入る。最高階が更新されなければ送信されない。同意していなければ送信されない。解除後は送信されない。ニックネームの不正（URL・13文字以上・空）が拒否される。
- 既存セーブ（v5）が壊れず、追加項目に既定値が入る。
- 既存テスト（`test_p1` 〜 `test_p5b1`、`test_save_migration`）がすべて通る。本編周回・回廊・深淵のBOT結果が変わらない。ビルドが再現できる。
- 420px幅で、ランキングのモーダルと設定が崩れない（スクリーンショットで確認）。
