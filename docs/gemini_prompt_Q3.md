# Gemini 向け指示書: Q3（スキルエフェクトの個別化・格上げ）

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で、Q3「スキルエフェクトの個別化・格上げ」を実装します。仕様と合格基準は `docs/change_Q3_fx_variety.md`（運営者承認済み）。Q1（`docs/dev_notes_Q1.md`）の演出コードとQ2（`docs/dev_notes_Q2.md`）の確認パネルが前提です。

### 0. 前提
- `src/` を編集し `python3 tools/build.py` で生成。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる（CRLFを保つ）。`src/assets/` は触らない。`window.__rogue`/`window.G` を残す。外部ライブラリ・画像は追加しない（CSS・DOM・インラインSVGのみ）。
- 作業は `dev`。`main` には push しない。push は従来どおり（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄）。既存コミットの書き換え・force push はしない。

### 1. やること
`docs/change_Q3_fx_variety.md` の2〜3章をすべて実装する。要点:
1. 斬撃6・魔法8・大技/奥義8・回復10（計32スキル）に、それぞれ**固有の演出**（モチーフ・動き・形）を作る。色違い・本数違いだけで済ませない。3章の表のモチーフに沿う。`SKILL_FX_MAP` を、各スキルに固有の識別子（signature）を持つ形に拡張する（未登録IDは従来の分類の汎用演出にフォールバック）。
2. **ティア制**: 威力の高いスキルほど、演出時間が長い・要素が多く大きい・画面を覆う範囲が広い・閃光とぶれが強い。最上位（絶対零度・創世の光・永劫の祈りなど）は最も豪華に。ティアが実データ（倍率・ヒット数・MP・回復量）と矛盾する場合は実データに合わせ、報告に書く。
3. 上限: 同時要素は最大12個（16個まで引き上げる場合は報告）、長さは最大1200ms、`transform`/`opacity` 中心。ゲーム速度による短縮（最短150ms）、前の演出の即時終了、try/catch 隔離、reduced-motion、戦闘エフェクトOFF、Q2パネル（`target` 引数）の動作はそのまま維持。
4. 強化（バフ）の演出は変えない。演出は表示のみで、ダメージ計算・乱数・タイミング・BOT結果に影響させない。

### 2. 守ること（厳守）
- 数値・バランス・BOT結果・セーブ形式(v8)・`to_dev` の分離を変えない。Q1/Q2の機能を壊さない。
- 仕様と矛盾する判断は勝手に決めず「要確認」と書く。
- `tools/test_q3.py`（新規）を追加し、`README.md` に実行方法を書く。合格基準1〜6をテストする（signatureの一意性、同分類内のティア順序、規定時間内に終了・要素数上限、高速連打、reduced-motion、360/390/420px）。
- 全テスト（test_p1〜最新、test_save_migration、test_variants、test_noskip、test_p8〜p10、test_modal_close、test_layout、test_ui1、test_ui2、test_q1、test_q2）が `RESULT: OK`。ビルドが `cmp` で再現できる。本編・塔・深淵のBOTが不変。テストを通すために判定を弱めない。
- 実装メモを `docs/dev_notes_Q3.md` に残す（スキルごとの演出内容・ティア・signature の一覧表を必ず入れる）。

### 3. 報告の形式（短く）
1. 32スキルの演出一覧（スキル名・ティア・モチーフの一行）
2. 合格基準1〜7の結果
3. テスト・ビルド・BOT結果
4. 要確認の点（ティアの調整、要素上限の変更など）

### 4. 今回やらないこと
強化（バフ）の演出変更、数値調整、新スキル、画像・音の追加、APK化。
