このファイルを Gemini にそのまま渡す。リポジトリ `ToMoreKey/rogue-demo` を読める状態（Gemini CLI / Code Assist / GitHub連携など）で使う。

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` を対象に、下記の「P0 基盤整備」を実装してください。回答と報告は日本語で、簡潔にお願いします。

### 0. 最初に読むもの
1. `docs/spec_volume_expansion.md`（仕様書。開発の正本。特に2章・6章・8章）
2. `README.md`
3. `index.html`（ゲーム本体。画像をbase64で埋め込んだ単一ファイル。約1.2MB）
4. `tools/bot.py`（自動プレイBOT。回帰テスト用）

仕様書と矛盾する判断が必要なときは、勝手に決めず、報告に「要確認」として書いてください。

### 1. プロジェクトの前提
- ゲームは単一の `index.html` で動く（GitHub Pagesで公開、PWA対応）。**最終成果物は今後も単一の `index.html`** とする。
- 既存の挙動（戦闘・成長・装備・スキル・セーブ）を**変えてはいけない**。P0は「中身を変えずに、作りやすくする」作業。
- テスト用フック `window.__rogue`（`tick`, `startRun`, `DUNGEONS`, `DIFFS`, `ACTS`, `newPlayer`, `setRng`, `setHeadless`, `noTimer` など）と `window.G` は**残す**。BOTがこれに依存している。
- セーブは `localStorage` のキー `rogue_test_save_v1`、形式は `{ v: 1, p, opts, sel, shopSel, autoSellRarity }`。
- 画像（キャラ・敵・アイコン）は私が別途生成して埋め込む。**画像データを書き換えない・削除しない**。

### 2. やること（P0）
**A. ソース分割とビルド**
- `src/` にゲームを分割する（例: `src/index.template.html`, `src/css/*.css`, `src/js/*.js`, `src/data/*.js`）。
- `tools/build.py`（Python3、標準ライブラリのみ）を作り、`src/` から単一の `index.html` を生成する。画像のbase64は `src/assets/` のファイル（またはJSON）から埋め込む。
- ビルド結果は、現行の `index.html` と**機能が同じ**になること。PWA用の `<link rel="manifest">`、メタタグ、Service Worker登録スクリプトも維持する。
- `README.md` にビルド方法（`python3 tools/build.py`）を追記する。

**B. データの切り出し**
- ダンジョン（`DUNGEONS`）、難易度（`DIFFS`）、敵、装備の基礎値（武器・防具・レア度倍率）、スキル定義、`TUNE` などの数値を、ロジックから分離して `src/data/` に置く。
- 今後の拡張（ダンジョンを9→15、難易度を3→5、★1〜5→★1〜9）が**データを足すだけ**でできる構造にする。ただし、**今は値を変えない**（現行の9ステージのまま）。

**C. セーブv2への移行処理**
- セーブ形式に `v: 2` を導入し、`v: 1` のセーブを読み込んだら自動で `v: 2` に変換する（`migrateSave(raw)` のような関数）。
- v2でも、現行のv1と同じ内容が失われないこと（所持品、装備、レベル、スキル、ゴールド、設定すべて）。
- 変換は将来 `v: 3` 以降も連鎖できる形（`migrations = {1: fn, 2: fn, ...}`）にする。
- キー名は互換のため `rogue_test_save_v1` のままにするか、新キーにする場合は旧キーから読んで引き継ぐ。**旧セーブが消えないこと**。

**D. 回帰テスト**
- `tools/bot.py` を、ビルド後の `index.html` に対して動かせるようにする（既に動く。必要なら整える）。
- 追加で `tools/test_save_migration.py`（Playwright）を作り、v1セーブを注入して読み込み→v2になり、内容が保たれることを検証する。
- 「9ステージ全クリア」のBOT結果（下記）が、ビルド前後でほぼ同じになることを確認する。

### 3. 完成の判定（これを満たしたら完了）
1. `python3 tools/build.py` で `index.html` が生成でき、ブラウザで起動して、チュートリアル・戦闘・街・装備・スキル・ステータス画面が現行どおり動く。
2. `python3 tools/bot.py` の結果が現行と同等: 3回とも `done: true`、`runs` は91〜95前後、終了時 `lv` は31前後、`gold` は約14.4万〜14.8万G前後。ページエラー配列は空。
3. v1のセーブ（実際のゲームで作ったものを想定）を読み込み、内容が失われずにv2へ移行する。
4. 画像データ・見た目・UIが変わっていない。
5. `README.md` に、構成・ビルド手順・テスト手順が書かれている。

### 4. 守ること
- **作業は `dev` ブランチで行う。`main` には直接pushしない**（`main` はGitHub Pagesで公開中のデモ）。`dev` が無ければ作る。
- 1つのまとまりごとにコミットし、メッセージは日本語または英語で内容が分かるように。
- 秘密情報（トークン・鍵）を、コードにもリポジトリにも入れない。
- 外部ライブラリを追加しない（フォントのGoogle Fontsは現行どおり）。ビルドは標準ライブラリのみ。
- `index.html` を更新したら、`sw.js` の `CACHE` のバージョン番号（`rogue-v1` → `rogue-v2` ...）を上げる。
- 依存を増やさず、実装を過剰に抽象化しない。読みやすさを優先する。

### 5. 報告の形式
最後に次の4点だけ、短く報告してください。
1. 何を作ったか（ファイル構成）
2. BOTの結果（3回分）と、セーブ移行テストの結果
3. 仕様書と食い違った点・要確認の点
4. 次のP1（A〜C拡張）に進むために私が決めること

### 6. 今回やらないこと（次のフェーズ）
- 超級・極級、新ダンジョン、EXPの調整、装備の入手ルール変更、戦力値表示、ランキング、エンドコンテンツ。これらはP1以降。
- 画像の生成・差し替え。
