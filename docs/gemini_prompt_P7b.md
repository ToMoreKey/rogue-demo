## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で作業します。今回は P7b「本編序盤の難易度緩和」です。方針と合格基準は `docs/change_P7b.md` に書いてあります（運営者承認済み）。

### 0. 前提（これまでと同じ）
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる。`src/assets/` は触らない。
- `window.__rogue` と `window.G` を残す。外部ライブラリを追加しない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄する）。既存コミットの書き換え・force push はしない。
- セーブ形式・ID・画面・画像は変えない。

### 1. ゴール
P7a-2 の `TUNE` 一括引き上げで、本編の序盤（スキル未習得の新規プレイヤーがA初級を10回挑戦しても、クリアできない）が厳しくなった。**本編の序盤だけ、敵のHPと攻撃力を弱める。**

### 2. やること
1. `src/data/config.js` に「序盤緩和」の倍率表（ダンジョンID × 難易度ID → `{ hp, atk }`）を追加する。初期案は `docs/change_P7b.md` 2章。表にないものは 1.0。
2. `src/js/40_game.js` の敵生成（`TUNE.hpScale` と `TUNE.atkScale` を使っている箇所）で、**通常ダンジョンの本編ランだけ**（回廊・深淵では使わない）に倍率を掛ける。ボスにも同じ倍率。防御・経験値・ゴールド・ドロップは変えない。`TUNE` の既存値は変えない。
3. 倍率を調整し、`docs/change_P7b.md` 3章の合格基準を満たす。調整は小さい刻みで行い、そのたびに計測する。
4. 序盤の計測は、デバッグ2回目で使った方法（新規Lv1プレイヤー、`equipBest` あり、A初級を連続挑戦。スキル未習得／初期3SPで回復習得の2通り）で行い、結果の表を `docs/dev_notes_P7b.md`（新規）に載せる。A→B→C 初級の連続進行も確認する。
5. `tools/test_p7b.py`（新規）を追加し、`README.md` に実行方法を書く（倍率が本編のA〜Cだけに効く、回廊・深淵・後編で倍率が効かない、表にない組み合わせは1.0、序盤の計測が合格基準を満たす）。

### 3. 守ること（厳守）
- 本編の序盤（A〜C）以外の数値を変えない。`TUNE` の値、装備、スキル、ドロップ、回廊の祝福、深淵の呪いも変えない。
- 合格基準に収まらない場合は、勝手に基準や別の数値を動かさず、現状の結果を報告に載せて「要確認」と書く。
- 全テスト（`test_p1` 〜 最新、`test_save_migration`）が `RESULT: OK`。テストを通すために判定を弱めない（弱める場合は理由を報告に書く）。ビルドが再現できる（`cmp`）。
- BOT: `python3 tools/bot.py`（本編）、`--mode tower --bless opt` / `--bless rand`、`--mode abyss`。結果は加工せずそのまま報告に載せる。回廊・深淵は P7a 完了時点と完全に同じになること（本編は 3章の基準内）。
- 秘密情報をコード・コミット・ログ・報告に入れない。仕様と矛盾する判断は、勝手に決めず「要確認」と書く。

### 4. 報告の形式
最後に次だけ、短く報告してください。
1. 倍率表の最終値（変更前は全て1.0）
2. 序盤の計測結果（調整前→調整後。A初級のクリアまでの回数、A→B→Cの進行）
3. 本編・回廊・深淵のBOT結果（P7a完了時点との比較）
4. テスト・ビルド結果
5. 要確認の点

### 5. 今回やらないこと
- 序盤以外の調整、新機能、UI変更、画像の生成・差し替え、APK化。
