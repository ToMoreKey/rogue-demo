## 【プロンプト本文（ここから貼り付け）】

### 0. 前提（これまでと同じ）
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` を直接編集しない。`sw.js` の `CACHE` を上げる。
- `window.__rogue` と `window.G` を残す。外部ライブラリを追加しない。`src/assets/` は触らない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・報告・ファイルに出さない。使用後に変数を破棄）。
- 先に `docs/spec_volume_expansion.md`（5章「エンドコンテンツ」と、末尾の「P5 の決定事項」）、`docs/dev_notes_P1.md`〜`dev_notes_P4.md` を読む。仕様書の決定事項は変えない。

### 1. ゴール
最終ボスを倒した人（`p.ending` が真）向けに、無限回廊「天蓋の塔」を追加する。階層は無限で、敵が指数的に強くなる。10階ごとにボスが出て、倒すと「祝福」を3択で1つ選ぶ。全滅・撤退で終了し、到達階に応じて「回廊コイン」を得る。コインで神話装備・称号と交換できる。最高到達階は端末内に記録する（ランキング送信は P5b）。

### 2. やること

#### 2-1. 入口と解放
- 解放条件: `p.ending === true`（最終ボス撃破）。未解放のときは、ダンジョン一覧の末尾に「🔒 天蓋の塔（最終ボスを倒すと解放）」と表示する。
- ダンジョン一覧とは別枠のカード（「天蓋の塔」）として表示し、最高到達階・所持コインを見せる。
- 既存のダンジョンの仕組み（`startRun` など）を再利用してよいが、既存ダンジョンのバランスと挙動を変えてはならない。回廊専用の状態は `G.run.tower` のように分ける。

#### 2-2. 階層と敵
- 階層は無限（1階から）。1回のランは「挑戦する」で1階から始まる（途中階から始める機能は今回なし）。
- 敵は既存の全ダンジョンの敵（`DUNGEONS` の通常5種）から、階層に応じた帯のものをランダムに出す（例: 1〜10階は A〜C、…と帯を上げ、後半は J〜O の敵が中心。帯の割り当てを `docs/dev_notes_P5a.md` に表で残す）。画像は既存の `ENEMY_IMG` を使う。
- 10階ごとにボスが出る。ボスは既存ダンジョンのボスを帯に応じて使う（A〜O のボス。90階以降は繰り返し、名前に「第N層の」などの接頭辞を付けてよい）。**50階ごとの節目ボスは、O のボス（終焉神ニヒル）の上位種**にしてよい（怒り形態はなし）。
- 敵のステータスは階層に対して**指数的**に伸ばす（例: `hp,atk,def ∝ base × growth^(階)`。`growth` は BOT で調整）。1階あたりの戦闘の長さは、本編の基準（1階あたり約3.5〜4.4ティック）に近づける。装備・レベル・祝福が伸びないと詰む設計にする。
- 回廊では、敵の撃破で EXP とゴールドは通常どおり得られるが、**クリア報酬（`clearGold` `clearSp`）は無し**。装備ドロップは、★は帯に応じた上限（ボスは★8まで、50階以降のボスは★9も低確率）、**神話レアはドロップしない**（コイン交換のみ）。

#### 2-3. 祝福（10階ごとの3択）
- ボス（10階ごと）を倒すと、祝福の候補からランダムに3つ提示され、1つを選ぶ。選んだ祝福はそのランの間ずっと有効。同じ祝福は重ねて取れない（取得済みは候補から除く）。ランが終わると消える（セーブには残さない）。
- 祝福は**約30種**。次のカテゴリを混ぜる:
  - 純粋な強化（攻撃力+◯%、防御力+◯%、最大HP+◯%、最大MP+◯%、与えるダメージ+◯%、被ダメージ-◯%、スキルのCT短縮、回復量+◯%、EXP+◯%、ゴールド+◯%）
  - 取引型（リスクと見返り。例: 最大HPを半分失う代わりにドロップ率アップ、被ダメージ+◯%の代わりに攻撃力+◯%、MPが無くなる代わりに与ダメージ+◯%）
  - 成長型（階を重ねるごとに効果が増える。例: 10階ごとに攻撃力+◯%、倒すたびにHPを少し回復）
  - 特殊（初撃が必ずクリティカル、1回だけ戦闘不能から復活、ボスへの与ダメージ+◯%、宝箱・回復の泉の出現率アップなど）
- 各祝福に、名前・説明文（1行）・効果値を `src/data/` のデータ表（例: `tower.js`）で持たせる。新しい祝福はデータを足すだけで増やせる構造にする。実装を過度に複雑にしない（戦闘計算の倍率・加算フックに乗せる）。
- 画面: ボス撃破後に3択のモーダルを出す。現在取得済みの祝福の一覧を、回廊中いつでも見られる（戦闘画面の「祝福」ボタンなど）。

#### 2-4. 終了・記録・コイン
- 全滅（`defeat`）または撤退で終了する。通常のダンジョンの全滅ペナルティ（ゴールド・ドロップの扱い）は既存どおりにしてよいが、重すぎる場合は報告する。
- 終了時に到達階を確定し、`p.tower.best`（最高到達階）を更新する。到達階に応じて回廊コインを獲得する。式の案: 1階につき1コイン＋10階ごとにボーナス（10階=+5、20階=+12、…と増える）、50階以降は2倍。BOT で調整して決める。
- 結果画面: 到達階、取得した祝福、獲得コイン、最高到達階の更新を表示する。
- セーブ: `p.tower = { best, coins, totalCoins, titles: [], owned: {...} }` のような形を追加する。形式を変えるので `migrations` に v3→v4 を追加し、既存セーブ（v1/v2/v3）が壊れないこと、`tools/test_save_migration.py` を更新すること。バックアップ（`rogue_test_save_v1_bak_v3`）の仕組みはこれまでと同じ。

#### 2-5. 回廊コインの交換所（神話装備・称号）
- 交換所はダンジョン一覧の「天蓋の塔」カードから開く（または街に「交換所」を置く）。
- **神話装備（レア度「神話」、倍率6.0）**: 武器・防具の各部位で、★8の神話（ATK/DEF は ★8の基礎値×6.0倍の補正を受ける）を交換品にする。★9の神話は交換品に入れない（P5b で深淵の主の極めて低確率のドロップとして用意し、**ドロップ品のほうが交換品より高性能**になるようにするため）。値段の案: 武器 300コイン、防具 300コイン。BOT で最高到達階の見込みから調整する。1つ交換したら、同じものは何度でも買えるが、値段は据え置きでよい。
- 神話装備の特性（再鍛造で出る特性）は既存の仕組みに乗せる。★8→★9の強化（創世の欠片）は神話装備にも使える。
- **称号**: 到達階に応じた称号（例: 「塔の挑戦者」10階、「塔の踏破者」30階、「天蓋の覇者」50階、「天を衝く者」100階など）を、**コイン不要で到達すると自動取得**する。さらに、コインで買う称号も数種類用意する。装備している称号は、ステータス画面に表示するだけでよい（効果なし）。称号の数は10〜15種。
- 外見（スキン）は画像が無いので今回は作らない（P6 以降）。
- 交換所のUIは、既存のショップの形式に合わせる。ゴールド（G）と回廊コインを混同しない表示にする。

#### 2-6. BOT・バランス
- `tools/bot.py` に `--mode tower` を足す。クリア後の標準ビルド（Lv124〜130、★8〜9装備、スキル習得済み）の状態から、回廊に挑み、祝福をルールベースで選びながら、全滅するまで進む。結果として、到達階・取得コイン・使用ティックを出力する。
- 目標: **標準ビルドで、おおよそ40〜60階に到達する**（仕様書の「回廊50Fまで遊べる」）。3シードで大きくばらつかないこと（±20%以内）。祝福の選び方（ランダム／最適）で到達階がどう変わるかも報告する（祝福が効いているかの確認）。
- 回廊が重すぎない（100階以上でも画面・メモリが問題ない）。階層表示は「42F」のように短く表示する。
- 既存の周回モード（A〜O 全75セル）の結果が P4 から変わらないこと（`model_hours` 20.85〜20.94、ラン数490〜493、Lv124）。

#### 2-7. テスト（`tools/test_p5a.py` を追加し、`README.md` に実行方法を書く）
- 解放: `p.ending` が偽なら入れず、真なら入れる。
- 階層: ボスが10階ごとに出る。敵のステータスが階層で単調に増える。
- 祝福: ボス撃破後に3択が出る。選ぶと効果が反映される。同じ祝福は重複しない。ランの終了で消える。祝福データの全種が、効果の適用でエラーにならない。
- 終了とコイン: 全滅・撤退で終了し、最高到達階とコインが更新される。コインの計算式の値。
- 交換所: 神話装備（★8）が買え、神話レアとして装備でき、戦力値が出る。コイン不足では買えない。★9の神話は売られていない。称号の自動取得と購入。
- 回廊でのドロップ: 神話レアが出ない。★9はボス（50階以降）の低確率のみ。
- セーブ移行（v1→最新、v2→最新、v3→最新）と、回廊のセーブ項目の保存・読み込み。
- 既存テスト（`test_p1` 〜 `test_p4`、`test_save_migration`）がすべて通る。ビルドが再現できる。
