## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で、下記の「P6c チュートリアル・ヘルプ・PWA」を実装してください。回答と報告は日本語で、簡潔にお願いします。

### 0. 前提（これまでと同じ）
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる。`src/assets/` は触らない（画像を新規に作らない。既存の `ENEMY_IMG`・装備アイコン・CSS・文字・絵文字で作る）。
- `window.__rogue` と `window.G` を残す。外部ライブラリを追加しない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・報告・ファイルに出さない。使用後に変数を破棄）。
- **本編・回廊・深淵のバランスとBOT結果を変えない**（本編周回: ラン数490〜493、`model_hours` 20.85〜20.94、1階あたりティック4.06〜4.13、Lv124。回廊: 最適59/64/69、ランダム51/53/59。深淵BOTも変えない）。報酬は**回廊コインと称号だけ**にして、本編のゴールド・SP・EXP・ドロップには影響させない。
- セーブは追加のみ。既存セーブ（v1〜最新）が壊れないこと。形式を変える場合は `migrations` に追加し、`tools/test_save_migration.py` を更新する。
- 420px幅で画面が崩れないこと（横スクロールが出ない）を、スクリーンショットで確認する。

### 1. ゴール
本編クリア後に解放される機能（回廊・深淵・極意・神話装備・図鑑・実績・ランキング）を、プレイヤーが迷わず理解できるようにする。PWA の情報を更新する。

### 2. やること

#### 2-1. 解放のお知らせ（本編クリア時）
- 「ゲームクリア」のモーダルを、閉じたあとに、解放された機能の一覧を見せる「お知らせ」を1回だけ出す（既存のクリアモーダルを壊さず、閉じたあとに続けて表示）。内容: 天蓋の塔（回廊）、深淵（全ダンジョンの極級クリアで解放）、極意（SPの新しい使い道）、進化第3段階、図鑑・実績。各項目に「見る」ボタン（該当画面へ移動）。
- 深淵が解放されたとき（全15ダンジョンの極級クリア済みになった時点）、1回だけトーストで知らせる。
- 既に本編クリア済みのセーブでは、お知らせは出さない（出したかどうかを記録するフラグを追加。既存セーブには「出し済み」として入れる）。

#### 2-2. ヘルプ画面の更新
- 既存のヘルプ画面に、後編以降のセクションを追加する（折りたたみ式の項目でよい）。内容（各3〜6行。ゲーム内の用語に合わせる）:
  - 天蓋の塔: 階層は無限、10階ごとのボスと祝福（3択）、5階ごとの2択、回廊コインの使い道（神話装備・称号）。
  - 深淵: 難度1〜10、呪いが累積すること、50階固定、深淵の主、★9の神話が低確率で出ること。
  - 極意と進化第3段階: 解放条件（本編クリア）、SPの使い道、リセット。
  - 装備: ★6〜9の強化素材（上級石・時の欠片・機神の核・創世の欠片）、神話レア、複数特性。
  - 図鑑・実績・称号。
  - ランキング: 同意した人だけ送信される、送信内容（ニックネームと最高到達階）、運営者の確認後に掲載される（すぐには反映されない）。
- 既存のヘルプ（序盤の操作説明）の文章は変えない。目次（上部のリンク）があれば更新する。

#### 2-3. チュートリアル
- 序盤のチュートリアル（`70_tutorial.js`）は**変えない**。回廊・深淵は、2-1のお知らせとヘルプで説明する（新しいチュートリアルは足さない）。

#### 2-4. PWA の更新
- `manifest.json` の `description` を、現在のボリューム（全15ダンジョン、無限回廊、深淵）に合わせて更新する。`name`・アイコン・`start_url`・`display` は変えない。
- `sw.js` の `CACHE` を上げ、プレキャッシュの対象が現在のファイルと合っているか確認する（`index.html`、`manifest.json`、アイコン、`data/ranking.json` はネットワーク優先で、プレキャッシュに入れない）。
- オフラインで、起動・戦闘・街・回廊・深淵が動き、ランキングだけが「オフライン」表示になることを、Playwright で確認する（`context.set_offline(True)` を使用）。

#### 2-5. 公開前チェック（`docs/release_checklist.md` を更新）
- 私（Claude）が `docs/release_checklist.md` を作成済み。あなたは、その表の「Gemini確認」列を埋める: 各項目を実際に確認し、結果（OK／NG・メモ）を記入する。確認できない項目（実機・外部サービス）は「要人間確認」と書く。

#### 2-6. テスト
- `tools/test_p6c.py` を追加し、`README.md` に実行方法を書く。内容: クリア時のお知らせが1回だけ出る（既存の出し済みセーブでは出ない）、各「見る」ボタンの遷移、ヘルプに新しい項目がある、`manifest.json` の説明文、オフライン動作、420pxで横スクロールなし。
- 既存テスト（`test_p1` 〜 `test_p6b`、`test_save_migration`）がすべて通る。本編周回・回廊・深淵のBOT結果が変わらない。ビルドが再現できる。

### 3. 守ること
- 作業は `dev`。1つのまとまりごとにコミット。仕様を `docs/dev_notes_P6c.md`（新規）に残す。
- 秘密情報（トークン・鍵）を、コード・コミット・ログ・報告に入れない。
- 仕様書と矛盾する判断が必要なときは、勝手に決めず、報告に「要確認」と書く。

### 4. 報告の形式
最後に次だけ、短く報告してください。
1. 2-1〜2-6 のそれぞれ（できた／できなかった）
2. 本編周回・回廊・深淵のBOT結果が変わっていないこと
3. 公開前チェックリストの結果（OK／NG／要人間確認の件数と、NGの内容）
4. 仕様書と食い違った点・要確認の点

### 5. 今回やらないこと
- 新機能、バランス調整、画像の生成・差し替え、APK化（C）。
