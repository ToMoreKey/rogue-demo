# Gemini 向け指示書: Q2（テスト版のエフェクト確認パネル）

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で、Q2「テスト版のエフェクト確認パネル」を実装します。仕様と合格基準は `docs/change_Q2_fx_debug.md`（運営者承認済み）。Q1（`docs/change_Q1_battle_fx.md`、`docs/dev_notes_Q1.md`）で作った演出コードを使います。

### 0. 前提
- `src/` を編集し `python3 tools/build.py` で生成。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる（CRLFを保つ）。`src/assets/` は触らない。`window.__rogue`/`window.G` を残す。外部ライブラリ・画像は追加しない。
- 作業は `dev`。`main` には push しない。push は従来どおり（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄）。既存コミットの書き換え・force push はしない。

### 1. やること
`docs/change_Q2_fx_debug.md` の2章をすべて実装する。要点:
1. 「データ」タブの既存の dev 専用ボタン群（`IS_DEV_BUILD` のときだけ出る）に「🎬 エフェクト確認」を追加し、モーダルを開く。本番では出ない・開けない。
2. モーダル: 確認用ミニアリーナ（sticky）＋分類別の全スキルボタン＋操作（速度、激昂ON/OFF、激昂の瞬間、バフオーラ、敵切替、停止）。実戦闘と同じ演出コードを使う。演出関数が実戦闘のIDを直接参照しているなら、対象ルートを渡せるよう最小限にリファクタする（実戦闘の見た目・挙動は変えない）。
3. パネルはゲーム状態・セーブに一切影響しない。閉じたら演出要素・クラス・タイマーを全て消す。設定OFFでもパネル内は再生する。`prefers-reduced-motion` は尊重する。

### 2. 守ること（厳守）
- 本番ビルドに出さない。数値・バランス・BOT結果・セーブ形式(v8)・`to_dev` の分離を変えない。Q1の演出の見た目・挙動を変えない。
- 仕様と矛盾する判断は勝手に決めず「要確認」と書く。
- `tools/test_q2.py`（新規）を追加し、`README.md` に実行方法を書く（合格基準1〜5）。
- 全テスト（test_p1〜最新、test_save_migration、test_variants、test_noskip、test_p8〜p10、test_modal_close、test_layout、test_ui1、test_ui2、test_q1）が `RESULT: OK`。ビルドが `cmp` で再現できる。本編・塔・深淵のBOTが不変。テストを通すために判定を弱めない。
- 実装メモを `docs/dev_notes_Q2.md` に残す。

### 3. 報告の形式（短く）
1. 実装内容（パネルの構成、演出関数のリファクタ内容）
2. 合格基準1〜6の結果
3. テスト・ビルド・BOT結果
4. 要確認の点

### 4. 今回やらないこと
本番向けの機能追加、数値調整、新スキル、画像・音の追加、APK化。
