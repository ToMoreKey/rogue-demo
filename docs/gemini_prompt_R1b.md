# Gemini 向け指示書: R1b-1（キャラ専用スキルのデータ・仕組み）

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で、R1b-1「キャラ専用スキルのデータ・仕組み」を実装します。仕様は `docs/change_R1b_new_skills.md`（運営者承認済みの R1 `docs/change_R1_char_classes.md` の続き）、前提は R1a（`docs/dev_notes_R1a.md`、`src/data/char_trees.js`）です。**今回は R1b-1 のみ**（個別エフェクトは R1b-2、バランス調整は R1c で私が行います）。

### 0. 前提
- `src/` を編集し `python3 tools/build.py` で生成。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる（CRLFを保つ）。`src/assets/` は触らない。`window.__rogue`/`window.G` を残す。外部ライブラリは追加しない。
- 作業は `dev`。`main` には push しない。push は従来どおり（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄）。既存コミットの書き換え・force push はしない。

### 1. やること（`docs/change_R1b_new_skills.md` の §2〜§4）
1. **新パッシブ2つ**: `crit20`（クリティカル率+20%）、`swift10`（全スキルCT-1、最低1）を `passiveBonus` と戦闘計算（クリティカル判定、CTのセット箇所）に追加。塔の `ctRed`、深淵の `ctAdd`、極意の `critAdd` と正しく合成する。
2. **汎用バフ**: `SK` のバフに `gen: { turns, atkMult?, defMult?, takenMult?, allMult? }` を持てるようにし、`useSkillEffect`・攻撃力/防御/被ダメ計算に反映（ターン経過で切れる）。ID固定の既存バフの挙動は変えない。ログは自動生成。
3. **新規スキル28個**の定義（`SK`）と、4キャラのツリー（`src/data/char_trees.js`）の本設計への差し替え（§3.1〜3.4の表どおり。`// TODO(R1b)` は全て消す）。全スキルに `desc` を付ける。ステラの30SP奥義は `swordGod` に差し替え。シリアの主ツリー・第2ツリーに攻撃スキルを追加（チュートリアルの3SPヒールは変えない）。
4. `SKILL_FX_MAP` に、新スキルの仮の `cat` だけ登録（演出は同分類の汎用のままでよい。個別エフェクトは R1b-2）。未登録でも落ちないこと。
5. `tools/bot.py`: キャラ別の装備スキル優先リスト（§3 の「BOT装備」）を持たせ、`--char` で4キャラとも完走するようにする。
6. 説明表示: ステータス「スキル」タブでパッシブ・新スキルの `desc` が正しく出る。CT表示（スロット）が `swift10` で正しい。

### 2. 守ること（厳守）
- 既存スキルの数値・挙動、戦闘・演出（Q1〜Q3）・塔・深淵・P8〜P10・R1aの仕組み・`to_dev` の分離を壊さない。ステラのBOT参考結果（周回495/498/509、敗北10/7/25）から大きく外れない。
- 数値は初期案どおりに入れる（調整は R1c）。仕様と矛盾する判断は勝手に決めず「要確認」と書く。
- `tools/test_r1b.py`（新規）を追加し、`README.md` に実行方法を書く（合格基準1〜4）。
- 全テスト（test_p1〜最新、test_save_migration、test_variants、test_noskip、test_p8〜p10、test_ui1、test_ui2、test_q1〜q3、test_r1a）が `RESULT: OK`。ビルドが `cmp` で再現できる。テストを通すために判定を弱めない（直した場合は理由を報告）。
- 実装メモを `docs/dev_notes_R1b.md` に残す（新スキル一覧、汎用バフの仕様、パッシブの合成方法）。
