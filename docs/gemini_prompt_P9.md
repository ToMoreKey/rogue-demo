# Gemini 向け指示書: P9（ゲーム内の不具合報告）

運営者がフォームを作る前でも依頼できる（`reportUrl` は空のまま実装する）。

---

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で作業します。今回は P9「ゲーム内の不具合報告」です。仕様と合格基準は `docs/change_P9_bugreport.md` に、運用は `docs/bugreport_setup.md` に書いてあります（運営者承認済み）。

### 0. 前提（これまでと同じ）
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる。`src/assets/` は触らない。新しい `src/` ファイルを足したら `tools/build.py` の `JS_ORDER`（データは対応する並び）に登録する。
- `window.__rogue` と `window.G` を残す。外部ライブラリを追加しない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄する）。既存コミットの書き換え・force push はしない。
- 本番ビルドとテスト版ビルド（`python3 tools/build.py <出力> --variant dev`）の分離を壊さない。**注意: `tools/build.py` の `to_dev` はランキングの `formUrl: '...'` を正規表現で1箇所だけ置換している。不具合報告のURLのキーは `reportUrl` にして、この置換と混ざらないようにする。** テスト版でも不具合報告は送信できる（診断情報の `build=dev` で区別する）。

### 1. ゴール
プレイヤーが、ゲーム内から不具合・バランス・要望を報告できるようにする。送信先は運営者の Google フォーム（ランキングと同じ方式）。

### 2. やること
`docs/change_P9_bugreport.md` の 3-1〜3-5 をすべて実装する。要点:
1. ヘルプ画面の下部と、ステータス画面の「データ」パネルに「不具合・ご意見を送る」ボタン。
2. 報告画面（モーダル）: 種類の選択、内容（5〜500文字、文字数カウンター）、送られる診断情報の表示、同意チェック（必須）、送信／キャンセル。下端のボタンは常に見える位置に置く。
3. 診断情報は `build=; ver=; vp=; ua=; lv=; dg=; fl=; view=; err=` の1行。`ver` は `tools/build.py` が `sw.js` の `CACHE` から読み取って `APP_VERSION` に埋める（手書きしない）。`ua` はブラウザ名とOS名だけ。`err` は `window.onerror` / `unhandledrejection` の直近3件（各120文字まで）。セーブデータ・ニックネーム・個人情報は含めない。
4. 送信は `fetch(reportUrl, { method: 'POST', mode: 'no-cors', body: FormData })`。60秒に1回まで。オフライン・失敗時は端末に最大5件保存し、次回起動時とオンライン復帰時に再送する。
5. 設定は `src/data/bugreport.js` の `BUGREPORT_CFG`。`reportUrl` などは**空のまま**にする（運営者がフォームを作ってから、Claude が値を入れる）。空のときは、ボタンは出すが「準備中です」と表示して送信できない。
6. ヘルプ画面に、報告の案内を1項目だけ追加する（既存の文章は変えない）。

### 3. 守ること（厳守）
- ゲームの数値・バランス・BOT結果、セーブのバージョン（v8）と構造は変えない。キューは別キーに置く。
- 秘密情報（トークン等）をゲームに入れない。外部ライブラリを追加しない。
- 仕様と矛盾する判断は、勝手に決めず「要確認」と書く。
- `tools/test_p9.py`（新規）を追加し、`README.md` に実行方法を書く。`docs/change_P9_bugreport.md` の5章（合格基準）の1〜7をすべてテストする。送信のテストは Playwright の通信傍受で行い、実際のフォームには送らない。基準7は、ゲームが出す診断情報を `tools/make_bug_report.py` に食わせて確認する。
- 全テスト（`test_p1`〜最新、`test_save_migration`、`test_variants`、`test_noskip`、`test_p8`、`test_modal_close`、`test_layout`）が `RESULT: OK`。ビルドが再現できる（`cmp`）。本編・回廊・深淵のBOT結果が変わらない（本編: ラン数490〜510、`model_hours` 20.8〜21.2、Lv124。回廊・深淵は P7b 完了時点と同じ）。テストを通すために判定を弱めない（弱める場合は理由を報告に書く）。
- 実装メモを `docs/dev_notes_P9.md`（新規）に残す。

### 4. 報告の形式
最後に次だけ、短く報告してください。
1. 3-1〜3-5 とヘルプ追記の結果（できた／できなかった）
2. 合格基準1〜7の結果
3. テスト・ビルド・BOT結果
4. 要確認の点

### 5. 今回やらないこと
- フォームの作成・実際の送信先の設定、クラウド連携、スクリーンショット添付、数値調整、新機能、画像の生成・差し替え、APK化。
