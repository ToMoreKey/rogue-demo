## 3. セーブの安全性（Q4-1）

### 現状
- `localStorage`（`SAVE_KEY`、`SAVE_VERSION=9`）に保存。旧版からの移行時はバックアップキー `_bak_v*` を作成。
- IndexedDB への自動バックアップ（`35_backup.js`）と、書き出し/取り込み、バックアップ促しトーストあり。dev/本番でキーは分離済み。
- 保存失敗・容量超過・複数タブ同時操作・壊れた JSON に対するユーザー向けの通知は不十分（`try/catch` で握りつぶしている箇所がある）。

### やること
1. **保存の失敗を検知して知らせる**
   - `save()` が例外（容量超過・Storage 無効）のとき、画面上部に常駐の警告バナー「⚠ セーブできていません。設定の『バックアップ書き出し』で退避してください」を表示。成功したら自動で消える。
   - プライベートブラウズ等で Storage 自体が使えない場合は、起動時に一度だけ説明を表示（保存されない旨）。
2. **壊れたセーブからの復旧**
   - 読み込み時に JSON が壊れている／必須項目が欠けている場合、「セーブデータを読み込めません」画面を出し、①IndexedDB の自動バックアップから復元 ②書き出しファイルを取り込む ③新規開始（確認2段階）を選べる。壊れた原文は `rogue_*_corrupt_<日時>` に退避して上書きしない。
3. **自動バックアップの世代管理**
   - IndexedDB に直近3世代を保持（例: 起動時／ダンジョン帰還時／大きな進行（初踏破・極意解放）時、ただし1日あたりの書き込み回数に上限）。復元画面で日時・Lv・戦闘力を並べて選べる。
4. **複数タブの競合防止**
   - `storage` イベントで他タブの保存を検知し、「別のタブで更新されました。再読み込みしてください」を表示して、古いタブからの上書き保存を止める。
5. **バックアップ導線の見直し**
   - ステータス>データに「最終バックアップ: ○日前」を表示。7日以上なら控えめな促し（既存トーストの条件を整理）。
6. **移行テストの拡充**
   - 旧版（v1〜v9）のセーブを読み込み→保存→再読込でデータが保たれること、`autoEquipV2` 等の新キーが欠けた旧セーブでも落ちないことを確認。

### 受け入れ基準（自動テスト）
- `localStorage.setItem` を例外にした状態で警告バナーが出る／復帰で消える。
- 壊れた JSON・必須項目欠落で復旧画面が出て、新規開始しても壊れた原文が退避される。
- バックアップが3世代で打ち切られ、選んだ世代から復元できる。
- 2タブ目の保存で1タブ目に警告が出て、1タブ目の保存が止まる。
- 既存 `test_save_migration` 全件 OK（期待値を要する変更のみ更新）。

### 決めてほしいこと
- 復旧画面の文言のトーン（現状の砕けた口調に合わせる想定で進めます）。

## 2. 画面・操作の仕上げ（Q4-2）

### 2-A スキル画面・スキルツリー
**現状:** 装備タブは武器/防具ボタンと比較表に刷新済み。スキル（`renderSkillTrees` / `renderSkillSlots`）は旧来の見た目で、習得で何が変わるか分かりにくい。
**やること**
- **SP割り振りの事前表示:** 「+1 SP」ボタンの横に、習得・強化で変わる内容（スキルなら効果の要約、パッシブなら ▲ 数値）を表示。戦闘力が変わる場合は `▲+N` を併記。
- **スロット装備の見やすさ:** S1〜S3 を横並びのスロットカードにし、タップで装備候補（習得済みスキル）を選ぶ。装備中スキルの MP・CT・効果を一覧に出す。「外す」ボタンを追加。
- **ツリーの進行表示:** 各ツリーの進捗バー（習得 n / 全体 m）、次に習得できるノードを強調、未解放ノードは解放条件を表示。
- **リセット:** ツリー単位の振り直し（`spAllocReset`、確認2段階・ゴールド費用）と極意のリセットは**既に実装済み**。今回は①費用と戻るSPをボタンに明示 ②ツリー単位だけでなく「全ツリーまとめてリセット」を追加（費用は各ツリーの合計、確認2段階）③リセット後の戦闘力変化を表示。
**受け入れ基準:** 各ツリーに進捗表示が出る／SP 割り振り前後の説明と戦闘力差が出る／スロットの装備・解除が動く／チュートリアル（ヒール習得→装備）が従来どおり完走（`tutAllowClick` の許可ボタンを維持）。

### 2-E 全ツリーまとめてリセット（決定）と、同一キャラの複数ビルド（決定）
**全ツリーリセット（ゲーム内通貨）**
- ステータス>スキルに「全ツリーをリセット」ボタン。費用は **振っているツリーそれぞれの既存リセット費用（`skillResetCost` ＝ Lv×50G・最低50G）の合計**。確認は2段階（1回目で費用と戻る SP を表示、2回目で実行）。リセット後は SP が全て戻り、装備中スキルは条件を満たさなくなったものを外す（既存のツリー単位リセットと同じ処理を全ツリーに適用）。戦闘力の変化も表示。

**複数ビルド（スロット拡張）**
- **ビルドとは:** キャラ1人ごとの「SPの振り方（各ツリー）＋装備スキル（S1〜S3）」のセット。装備（武器・防具）・Lv・極意は共通。
- **スロット数:** 既定1。有料アイテム **「ビルドの書」** を使うごとに +1（最大3）。
- **「有料」の扱い:** 実課金ではなく**ゲーム内通貨（G）で購入するアイテム**として実装する（**1冊目は安め、2冊目から高め**。仮案: 1冊目 5,000G／2冊目 60,000G。BOT で G の収支を見て最終決定）。売り場は売却ショップ（トト）。※実課金（決済）を想定する場合は、PWA に決済基盤が無いため別途設計が必要です。
- **SP の扱い:** 各ビルドは「そのキャラが獲得した SP の総量」を持ち、ビルドごとに独立して振る（ビルド2を作ると、手持ちの全 SP が未割り振りの状態で始まる）。以降に獲得する SP は**全ビルドに同量加算**。結果として、どのビルドでも同じ総 SP で組める。
- **切り替え:** 街でのみ可能（探索中は不可）。無料。ステータス>スキルの上部に「ビルド1／2／3」タブ。名前は8文字まで編集可（既定「ビルド1〜3」）。切り替え時に戦闘力の増減を表示（既存の通知・残像を使用）。
- **データ:** `p.chars[cid].builds = [{ name, skillPts, equippedSkills, spFree }]`、`activeBuild`、`p.buildSlots`（購入数）。`SAVE_VERSION` を上げ、既存セーブは「ビルド1＝現在の状態」に移行（移行テスト追加）。キャラごとにビルドを持つ。
- **UI:** 未購入スロットは鍵つきで表示し、「ビルドの書（ショップで購入）」を案内。
- **受け入れ基準:** 購入で最大3まで増える／切り替えで SP・装備スキルが独立している／獲得 SP が全ビルドに加算される／探索中は切り替え不可／旧セーブが移行されて落ちない／全ツリーリセットが合計費用で動き2段階確認が必要／既存テスト OK（バランス基準値は不変）。

### 2-B 小さい画面・横画面
**現状:** 568px 高さの端末で戦闘中の撤退ボタンが見切れる既知の不具合。
**やること**

- 各画面（街・各施設・ダンジョン選択・戦闘・結果・ステータス5タブ・ヘルプ5タブ・図鑑・モーダル）を全ビューポートで撮影し、①横スクロール ②ボタンの見切れ ③タップ領域 44px 未満 ④固定バーと本文の重なり をチェック。
- 戦闘画面は高さが低い端末でボタン群を 1 行に圧縮（アリーナの縦を縮める）、撤退ボタンは常に画面内。
- `safe-area-inset`（ノッチ・ホームバー）を下部ナビ・モーダルに反映（未対応箇所を追加）。
**受け入れ基準:** 上記ビューポート×主要画面で横スクロールなし・撤退/主要ボタンが可視（Playwright で自動検査: `getBoundingClientRect` がビューポート内）。

### 2-D ダンジョン選択

## 1. 遊びの手触り（Q4-3）

### 1-A 初めて遊ぶ人の導線
**現状:** チュートリアルは7ステップ（ダンジョンA→戦闘→HP半分で撤退→ステータスでヒール習得→装備→完了）。終了後の「次にやること」の案内が弱く、今回追加した機能（戦闘力・装備切り替え・NPC）の説明が無い。
**やること**
1. **「はじめの目標」カード**（街の広場の最上部、チュートリアル後〜達成まで）: 5つの小目標を順に表示し、達成でチェック＋小さな祝福。
   例: ①ダンジョンAを踏破 ②装備を切り替える（装備タブ）③SPでスキルを1つ習得 ④戦闘力ランク「駆け出し」到達 ⑤ダンジョンBに挑戦。
   各目標に「そこへ行く」ボタン（該当画面へ遷移）。全達成で消える（ステータス>データから再表示可）。
2. **初回ヒント（1回だけ）:** 初めて ①装備ドロップを得た結果画面 ②ステータスを開いた時 ③ショップに入った時、に短い吹き出しヒント（戦闘力・装備の切り替え・売却の意味）。「わかった」で閉じ、`p.hints` に記録。
3. **チュートリアルのスキップ/やり直し:** 既存セーブ・経験者向けに「スキップ」ボタン、ヘルプから再実行。
4. **ヘルプ連動:** ヘルプの「はじめかた」を実際の画面に合わせて更新（戦闘力・装備タブ・結果画面の切り替え・自動売却の説明）。
**受け入れ基準:** 新規開始で目標カードが出て、各条件の達成で自動チェックされる／ヒントが各1回のみ表示／スキップでチュートリアルが完了扱い／既存セーブでは目標カードが現在の進行に合わせて達成済みを反映。

### 1-B 戦闘の気持ちよさ（演出）
**現状:** スキル別の演出（Q1〜Q3, R1b）とダメージ数字（`popDamage`）あり。通常攻撃・被弾・撃破・ボス戦の「間」と「重さ」が弱い。
**やること**（すべて設定「演出」ONのときのみ。ノード上限・時間上限は既存規約に従う）
- **ダメージ数字:** 与ダメージの大きさで3段階のサイズ・色（通常/大/特大）、クリティカルは「CRITICAL!」＋フラッシュ、弱点/耐性があれば小さな注記。
- **ヒットストップと揺れ:** 大ダメージ・クリティカル・被弾時に 60〜90ms の停止感（CSS で敵/自分の `transform` を一瞬止める）と画面の微振動（強さは設定で弱/標準）。
- **撃破演出:** 通常敵は崩れて消える、ボスは大きな光と余韻（ドロップが出る流れを視覚化）。ボス登場時は名前バナーを1秒表示。
- **低HP警告:** HP 25% 以下で画面縁がゆっくり赤く脈動（reduced-motion では静的な縁色のみ）。
- **レベルアップ/ドロップ:** レベルアップの帯演出、レア以上のドロップに光のエフェクト（ランク色）。
**受け入れ基準:** 各演出の DOM/クラスが条件どおりに出る（Playwright）／演出OFFで全て出ない／ノード数・時間が既存上限内／BOT・バランスに影響なし。

### 1-C サウンド
**現状:** 音は**一切ない**（`AudioContext` の使用なし）。
**方針:** 外部の音源ファイルは使わず、**WebAudio で合成**（ファイルサイズ増なし・オフライン対応・著作権の問題なし）。まず効果音(SE)、次にBGM。
**やること**
1. **音の基盤** `src/js/38_audio.js`: `Sound.play(name)`、マスター音量、SE/BGM別音量、ミュート。**最初のタップで AudioContext を resume**（iOS 対応）。バックグラウンド時は停止。
2. **SE（約20種）:** ボタン、攻撃（通常/スキル/魔法）、被弾、クリティカル、回復、バフ、撃破、ボス撃破、レベルアップ、ドロップ（コモン〜レジェンドで音階を上げる）、装備切り替え（強化=上昇音／弱体化=下降音、戦闘力の残像と同期）、売却/購入、勝利、敗北、撤退、エラー。
3. **BGM（簡易ループ・合成）:** 街／ダンジョン／ボス／塔の4曲程度。まずは短いシンプルなループで、品質に不満が出たら無効のまま出荷でも可（設定で OFF が既定）。
4. **設定:** ステータス>データに「効果音 / BGM」の ON/OFF と音量（3段階）。既定は **SE=ON（小音量）・BGM=OFF**（決定済み）。`opts` に保存。
5. **配慮:** 画面を見ていないときに突然鳴らない（自動再生は最初の操作後のみ）、音量は耳に優しい小さめ、連続再生の間引き（同種SEは 50ms 以内に重ねない）。
**受け入れ基準:** 設定のON/OFF・音量が `opts` に保存され反映される／ミュート時に `AudioContext` へ出力しない／同種SEの間引き／ヘッドレス（BOT）では無音で動作／テストは `Sound` の呼び出し履歴（フック）で検証。

### 決めてほしいこと（1）
- **決定済み:** SE を先行して実装し、BGM は簡易ループを付けて**OFF 既定**。**SE は最初から ON（小音量）**。設定（ステータス>データ）でいつでも切れる。

## 5. 世界観・コンテンツ（Q4-4）

### 5-A NPC の拡張
**現状:** 4施設（宿ミレイ・ショップトト・鍛冶ガンド・銀行ノア）にオリジナルの立ち絵と、入店/状況別/操作後のセリフ。
**やること**
1. **広場の案内人**（新NPC）: 街の広場に常駐し、状況に応じて「次にやること」を一言で促す（はじめの目標カードと連動）。
2. **進行度に応じた台詞の追加:** 初回入店／ダンジョン踏破数の節目／最終ボス撃破後（エンディング後）／塔・深淵の挑戦後で台詞が変わる。各NPC に 10〜15 本ずつ追加（現状は各約10本）。
3. **時間帯の台詞:** 端末の時刻（朝/昼/夜/深夜）で挨拶が変わる（例: 宿屋「おはよう！よく眠れたかい？」「夜更かしは体に毒だよ」）。
4. **タップで会話:** NPC の吹き出しをタップすると別の台詞（豆知識・世界観・ヘルプ導線）に切り替わる（同じ台詞が連続しないように）。
5. **立ち絵の表情差分:** 通常/喜び/驚きの2〜3種（SVG のパーツ差し替え）。強化成功・高額売却・大きな預入などで切り替え。
**受け入れ基準:** 開示段階①〜③の台詞にニヒルの名前が含まれない（全台詞を走査するテスト）／条件別の台詞が条件どおりに選ばれる（時刻・進行度は注入可能にしてテスト）／タップで前回と異なる台詞／表情差分が DOM に反映／既存の NPC テスト（`test_ui3` 基準7）OK。

### 5-B 図鑑・実績の見せ方
**現状:** 図鑑（敵・装備・称号）と実績があり、数値の一覧が中心（`openDex`）。
**やること**
- **NEW! バッジ:** 初めて見た敵・装備、達成直後の実績に「NEW」。図鑑ボタン（ステータス・街）にも未確認の数のドット。
- **発見・達成の演出:** 初発見でトースト＋短い光、実績達成は画面中央にバナー（称号名・報酬）。戦闘力の残像と同系の演出で統一。
- **コンプ率の可視化:** カテゴリ別の達成率バー、全体のコンプ率（％）と、あと何で次の報酬が貰えるか。
- **未発見のシルエット表示:** 敵は黒いシルエット＋「？？？」、装備は種類別の影。ヒント（出現するダンジョン）を1行。
- **フィルタ:** 未達成のみ／達成済みのみ、並び替え（ダンジョン順/ランク順）。
**受け入れ基準:** NEW が見た時点で消える／コンプ率の計算が一致／未発見がシルエットで出る／既存の図鑑・実績テスト OK。

### 決めてほしいこと（5）
- **決定済み:** 広場の案内人は「ルル」（好奇心旺盛な見習い案内人、口調は丁寧めで元気）。
- **決定済み:** 世界観は `docs/world_setting.md` のとおり（ニヒルは終盤まで伏せ、最初の目標は魔王ガルゼ。ミレイの夫の匂わせ・主人公4人との関係も採用）。NPC・図鑑・実績の台詞は同ファイルの「情報の開示段階」に従う（ネタバレ禁止の段階をテストで確認）。
