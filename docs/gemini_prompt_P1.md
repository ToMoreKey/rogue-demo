### 1. 前提（P0からの引き継ぎ）
- 作業は `src/` を編集し、`python3 tools/build.py` で単一の `index.html` を生成する。**`index.html` を直接編集しない**。
- `window.__rogue`（`tick` `startRun` `DUNGEONS` `DIFFS` `ACTS` `newPlayer` `setRng` `setHeadless` `noTimer` など）と `window.G` は**残す**（BOTが依存）。新しく追加した処理も、BOTから呼べるよう必要なものは `__rogue` に出す。
- 画像データ（`src/assets` と埋め込み画像）は**触らない**。見た目・UIの配色は変えない。
- 外部ライブラリを追加しない。ビルドは標準ライブラリのみ。
- **今は公開しない**。決定事項により、公開は全部完成後に一括で行う。`main` には push せず、`dev` に push する。マージは私が行う。
- push は、P0のときと同じ方法で行う（`github_personal` のトークンを設定ファイルから読み、その場の変数でヘッダーに渡す。トークンは画面・ログ・報告・ファイルに出さない。使い終わったら変数を破棄する）。
- `index.html` を更新したら、`sw.js` の `CACHE` のバージョンを上げる。

### 2. 今回のゴール
A〜Cの3ダンジョンを「5難易度」に広げ、成長・装備・ゴールドの土台を仕様書の方針に作り替える。ここで作る仕組みが、P2以降（D〜O）の基盤になる。**データを足すだけで拡張できる設計を保つこと。**

### 3. やること

#### 3-1. 難易度を3→5段階（超級・極級）
- `DIFFS` に超級（30階）・極級（40階）を追加する。`name` は「超級」「極級」、`tag` は任意（例: 「深層」「極致」）。
- 推奨レベル（`rec`）を、A=`[1, 9, 18, 30, 42]`、B=`[6, 14, 25, 37, 48]`、C=`[10, 20, 33, 45, 56]` にする。
- 各難易度の `pow`（敵の強さ）、`stars`（装備★の出現）、`rar`（レア度の出現）、`clearGold`、`clearSp` を、既存3難易度の伸びから延長して決める。目安: クリアSPは初級2→中級4→上級8→超級12→極級16。決めた値は `docs/dev_notes_P1.md` に表で残す。
- 超級・極級のボスは、既存ボスの「上位種」として**同じ画像を使い**、名前に接頭辞を付け（例: 超級=「古の」、極級=「鬼気を帯びた」）、色味（CSSの `filter: hue-rotate()` や `saturate` など）で区別する。画像の追加はしない。
- **解放ルール**: 超級は同じダンジョンの上級を、極級は同じダンジョンの超級をクリアすると解放される。A〜Cのダンジョン自体は、今までどおり最初から選べる（ダンジョンの解放は、D以降を追加するP2で使う。条件を `DUNGEONS` のデータで表せる形にしておく）。
- 未解放の難易度は、ダンジョン選択画面で鍵アイコン等で示し、選べないようにする。スマホ幅（420px）で5つの難易度が収まるレイアウトにする。

#### 3-2. クリア記録とセーブ v3
- 現状、セルごとのクリア記録が保存されていない（`stats.clears` の合計のみ）。ダンジョン×難易度ごとのクリア記録 `cleared: { A: { novice: true, ... } }` を追加し、セーブに保存する。
- **セーブを v2→v3 に移行する**（P0の `migrations` の仕組みで連鎖）。移行時の `cleared` は、そのセルの `rec` 以下のレベルのキャラなら「クリア済み」とみなす（既存プレイヤーが超級・極級に入れなくなるのを避けるため）。バッグ拡張用の `bagCap`（既定60）も追加する。
- 旧セーブ（v1・v2）が、内容を失わずに読み込めること。`tools/fixtures/` に v2 のサンプルを追加し、`tools/test_save_migration.py` を更新する。

#### 3-3. EXP配分の全体見直し
デバッグ部隊の指摘: 「経験値が多く、レベルが上がりすぎる。時間の約6割がレベル上げ（鍛錬）で、単調」。方針は、**ステージを順に進めるだけで推奨レベルに自然に届く**設計にし、周回（鍛錬）を必須にしないこと。
- 敵のEXP・必要EXP（`expNeed`）・`TUNE.expScale` などを調整する。**Lv30以降の必要EXPは段階的に重くする**（極級のボス撃破でLv56付近に届く設計。A〜Cの範囲では最大Lv56）。
- 検証のため、`tools/bot.py` に**線形モード**（`--mode linear`）を追加する。ダンジョンA→B→Cの順で、各難易度を初級→極級まで**各セル1回だけ**挑む（負けたときのみ、そのセルをやり直す）。次を出力する。
  - 各セルに入る直前のレベルと、そのセルの `rec` の差
  - 敗北回数、総ラン数、総ティック数（4倍速換算の戦闘時間）
- **合格基準**: 線形モードで、各セルに入る時点のレベルが `rec` の −3〜+2 の範囲に収まる。敗北は全体で5回以内。
- 現行の周回型BOT（既存モード）も、新しい15セル（A〜C×5難易度）を全クリアできること。

#### 3-4. 装備のドロップ上限と★6の追加
- 各ダンジョンに「ドロップできる最大★」を持たせる（データで表す）。**A=★4、B=★4、C=★5**。敵ドロップ・宝箱・行商人・イベントなど、装備が生成される経路すべてに適用する。★5はダンジョンC以降のみ。
- 既存セーブで持っている★5以上の所持品は、そのまま使えるようにする。
- ★6を追加する。基礎値は武器ATK80・防具DEF40（`WEAPON_BASE` `ARMOR_BASE` を延長）。名前は武器「竜殺しの大剣」・防具「古竜の鎧」。★5→★6の強化には**上級の強化石（`stone_hi`、Cで入手、現状未使用）**を必要とする（`STONE_REQ` に追加）。
- ★7（武器「時渡りの剣」ATK125、防具「雷霆の鎧」DEF62）は**データとして定義するだけ**にする。入手・強化の経路はP2（新素材が入るタイミング）で追加するので、今回は強化できなくてよい。
- ★6以上のキャラ絵は、★5の絵を使う（`skinTier` が★5以上を同じ絵にする）。アイコンは**★5のアイコンを流用**し、★数が分かる表示（例: 小さな「★6」のバッジ）を重ねる。新しい画像は使わない（アイコン画像は後で私がGeminiで生成して差し替える）。
- ★5防具の名前は、仕様書の決定どおり**キャラごとに別名**にする。今は全員「竜鱗の鎧」。名前の案を各キャラ（ルビー・ステラ・シリア・クロエ）に1つずつ考え、キャラの見た目（`src/data/skins.js` と、★5のテーマ）と合うようにする。案は報告に載せる。

#### 3-5. 戦力値と「おすすめ」マーク
- 武器・防具に**戦力値**を定義する。武器は「実効攻撃力」（基礎値 × レア度倍率 × 特性の倍率を反映）、防具は「実効防御力」。計算式は1か所の関数にまとめ、`docs/dev_notes_P1.md` に式を書く。
- 所持品・装備の一覧とアイテム詳細に、戦力値を表示する。
- 手持ちの各部位（武器・防具）で戦力値が最大のものに「おすすめ」マークを付ける。既存の `equipBest()`（自動で最強装備）と、判定が一致するようにする。

#### 3-6. ゴールドの使い道
目標は、全制覇時の余りゴールドを、現状（約14.5万G）の半分以下にすること。次を実装する。
1. **再鍛造**: ゴールドを払って装備の**特性（`PROPS`）を振り直す**（特性なしになる場合もある）。費用は `smithCost` と★・レア度に応じて決める。星やレア度は変えない。UIは街の鍛冶タブに追加する。
2. **ショップ**: 既存のショップ（`G.shopSel` を確認）を拡張し、強化石（初級・中級・上級）と薬を購入できるようにする。価格は高め（ドロップより割高。ただし常用できる範囲）にする。
3. **バッグ拡張**: `bagCap` を、60から最大120まで、10個ずつ購入して広げる。価格は段階的に上げる（例: 2,000G → 4,000G → ...）。`BAG_CAP` の固定値を `p.bagCap` に置き換える。
4. **鍛冶コストの見直し**: `smithCost` を「★の3乗」基準にする（例: `star³ × 係数 × レア度倍率`）。係数は、★5→6など高い★で高額になり、★2→3は今とほぼ変わらない水準に調整する。
5. **スキルリセットを有料化**: 今までの無料リセットに費用を付ける（レベル×一定額などで、極端に高くしない）。

BOTにも、これらの使い道（強化・再鍛造・バッグ拡張）を使う行動を足して、全制覇時の余りゴールドを測る。BOTが十分に使いきれないときは、報告に理由を書く。

#### 3-7. テストの整備
- 次の自動テストを `tools/` に追加し、`README.md` に実行方法を書く。
  - ドロップ上限: A・Bで何千回も装備を生成しても★5以上が出ない。Cでは★5が出る。
  - 難易度の解放: 上級未クリアでは超級に入れず、クリア後に入れる。超級・極級も同様。
  - 戦力値と `equipBest()` の判定が一致する。
  - セーブ移行（v1→v3、v2→v3）。
- `python3 tools/build.py` が再現可能（同じ入力で同じ出力）であること。

### 4. 完成の判定
1. ビルドして起動でき、チュートリアル・戦闘・街・装備・スキル・ステータスが動く。ブラウザのコンソールにエラーが出ない。
2. 線形モードで、各セルのレベルが `rec` の −3〜+2、敗北5回以内。
3. 周回型BOTが、A〜Cの15セルを全クリアする（3シードとも）。
4. 全制覇時の余りゴールドが約7万G以下（現状の約14.5万Gの半分以下）。届かない場合は、理由と改善案を報告する。
5. 3-7 のテストがすべて通る。v1・v2のセーブが失われずに移行する。
6. 画像・配色・既存画面のレイアウトに、意図しない変化がない。

### 5. 守ること
- 作業は `dev`。1つのまとまり（3-1、3-2、…）ごとにコミットする。
- 数値は一度に決め打ちせず、BOTで確認しながら調整する。決めた値と理由は、`docs/dev_notes_P1.md` に残す（他のAIが後で読む）。
- 仕様書は、必要な修正があれば `docs/spec_volume_expansion.md` を更新してよいが、**決定事項（8章）は変えない**。変更したら報告に書く。
- 秘密情報（トークン・鍵）を、コード・コミット・ログ・報告に入れない。

### 6. 報告の形式
最後に次だけ、短く報告してください。
1. 実装したこと（3-1〜3-7のそれぞれ。できた／できなかった）
2. 検証結果: 線形モードの表（セルごとのレベル差）、周回型BOTの3シード結果、余りゴールド、各テストの結果
3. 決めた数値（`pow`、クリアSP、`expNeed` の変更、`smithCost` の式、バッグ価格など）の要点
4. ★5防具の名前の案（4キャラ分）
5. 仕様書と食い違った点・要確認の点
6. 次のP2（新ダンジョンD〜F）に進むために、私が決めること・用意するもの（画像など）
