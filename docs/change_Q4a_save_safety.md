# 変更記録: Q4-1 セーブの安全性

## 実装
| 項目 | 内容 |
|---|---|
| 保存失敗の警告 | `save()` が例外（容量超過・保存不可）のとき、画面上部に赤い警告バナー＋「いまの内容をファイルに書き出す」。成功で自動的に消える。localStorage が失敗しても IndexedDB には保存を試みる。起動時に保存領域が使えない場合も警告。 |
| 破損セーブの保護 | セーブがあるのに読めない場合、原文を `..._corrupt_<時刻>` に退避（最大2つ）し、**上書きしない**（`G._saveBlocked`）。復旧画面（バックアップから復元／ファイル・コードから読み込む／新しく始める＝2段階確認）を表示。保護中は警告バナー＋「復旧画面を開く」。 |
| 自動バックアップ3世代 | IndexedDB に直近3世代（＋最新）を保持。世代の追加は、20分以上の間隔、または「起動時」「ダンジョン帰還時（`save(true)`）」の区切り。壊れた内容は世代に入れない。 |
| 復元UI | ステータス>データの「バックアップから復元」。日時・Lv・G・進行を並べ、**2段階確認**で戻す。戻す前の状態は `..._bak_restore` に退避。 |
| 別タブ競合 | `storage` イベントで他タブの保存を検知 → このタブは保存を止め、「再読み込み」付きの警告。 |
| バックアップ導線 | データ欄に「自動バックアップ：直近3世代（最新◯）」を表示、1週間以上書き出していなければ警告色の注意。 |
| チュートリアル | セーブ復旧系のボタンはチュートリアル中でも常に許可。 |

## 実装メモ
- 新ファイル `src/js/39_savesafe.js`（`build.py` の `JS_ORDER` に追加）。`save(milestone)` / `idbMirrorSave(force, rawOverride)` / `applyImportedSave`（保護解除）を変更。
- 破損の判定は `boot()` で「セーブキーがあるのに `load()` が失敗」。通常の取り込み失敗には影響しない。
- 新規 act: `openRecovery` / `recoverRestore` / `recoverNew` / `reloadPage`。

## テスト
- 新規 `tools/test_q4_save.py`（基準1〜6）: 保存失敗バナー／破損の退避・保護・2段階／3世代と復元／別タブ／キー欠落の旧セーブ／保存領域なしの起動。
- 既存の全テスト OK（`test_p8`・`test_save_migration` を含む）。`sw.js` は `rogue-v65`。

## 既知の制約
- 警告バナーは画面最上部に重なる（HUD の上）。閉じる操作は無く、原因が解消すると消える。
- IndexedDB が使えない環境では世代バックアップは作れない（localStorage のセーブは通常どおり）。
