あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で、下記の「P6b 実績・称号」を実装してください。回答と報告は日本語で、簡潔にお願いします。

### 0. 前提（これまでと同じ）
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる。`src/assets/` は触らない（画像を新規に作らない。既存の `ENEMY_IMG`・装備アイコン・CSS・文字・絵文字で作る）。
- `window.__rogue` と `window.G` を残す。外部ライブラリを追加しない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・報告・ファイルに出さない。使用後に変数を破棄）。
- **本編・回廊・深淵のバランスとBOT結果を変えない**（本編周回: ラン数490〜493、`model_hours` 20.85〜20.94、1階あたりティック4.06〜4.13、Lv124。回廊: 最適59/64/69、ランダム51/53/59。深淵BOTも変えない）。報酬は**回廊コインと称号だけ**にして、本編のゴールド・SP・EXP・ドロップには影響させない。
- セーブは追加のみ。既存セーブ（v1〜最新）が壊れないこと。形式を変える場合は `migrations` に追加し、`tools/test_save_migration.py` を更新する。
- 420px幅で画面が崩れないこと（横スクロールが出ない）を、スクリーンショットで確認する。

### 1. ゴール
実績（約36個）を追加し、達成で称号と回廊コインを得られるようにする。既存の回廊の称号・図鑑の称号と、一覧で見られる。

### 2. やること

#### 2-1. データ（`src/data/achievements.js`、新規）
- 実績のデータ表（新しい実績をデータを足すだけで増やせる構造）。各実績: `id`、`name`、`desc`、`cond`（達成条件の判定関数または条件オブジェクト）、`reward`（回廊コイン、称号ID）、`hidden`（隠し実績か）。
- **約36個**。次のカテゴリから、バランスよく選ぶ（最終的な一覧は `docs/dev_notes_P6b.md` に表で残す）:
  - 進行: 前編クリア、本編クリア（最終ボス撃破）、全ダンジョンの初級／上級／極級を制覇、各ダンジョン（A〜O）の極級クリア（まとめて「全15」の実績にしてよい）。
  - 装備: ★5・★6・★7・★8・★9の装備を初めて入手、神話装備を初めて入手、神話の★9を入手（隠し）、全キャラ分の★9装備（P5aまでの仕様で可能な範囲）。
  - 回廊: 10・30・50・70・100階に到達、祝福を累計50個取得、回廊コインの累計1,000枚。
  - 深淵: 難度1・3・5・7・10をクリア、深淵の主を3体とも撃破、★9神話をドロップ（隠し）。
  - 成長: Lv50・100・126・140に到達、SPを使い切る、極意を1項目最大にする、極意をすべて最大にする、進化スキル第3段階を取得。
  - 累計: 累計撃破数1,000・10,000・100,000、累計ラン回数100・500、累計ゴールド100万。
  - 図鑑（P6aと連携）: 敵図鑑コンプリート、装備図鑑コンプリート。
  - やり込み（隠し）: 「HP1で生還」「ノーダメージでボス撃破」など、既存の戦闘ログで判定できる範囲の1〜2個（難しければ省いてよい。報告する）。
- 称号は、実績ごと、または一部の実績で1つ（名前は実績にふさわしいもの。既存の回廊・図鑑の称号と重複しない）。称号の数は、実績の約半分（15〜20個）。

#### 2-2. 判定・記録・演出
- セーブに `p.ach = { [実績ID]: 達成した日付（ISO文字列） }` を追加する。
- 判定のタイミング: ラン終了時・撃破時・装備入手時・レベルアップ時・SP振り分け時・図鑑更新時など、条件に関わるイベントの直後。毎ティックの全件走査はしない（重くしない）。既存の統計（`p.stats` など）で足りない累計（累計ゴールド、祝福の累計取得数、回廊コイン累計）は追加で記録する。
- 達成時: 画面上部にトースト（実績名・報酬）。報酬の回廊コインと称号は自動で付与する（**本編クリア前は、コインを「保留」にして、本編クリア時にまとめて付与する**。本編のバランスに影響させないため）。
- 既存セーブでは、すでに達成している実績を、初回の読み込み時にまとめて判定して付与する（移行）。バージョンを上げて `migrations` に追加する。

#### 2-3. 画面
- 図鑑のモーダルに「実績」タブを追加する（または、ステータスに「実績」ボタン）。達成数（例: 「達成 12 / 36」）、カテゴリごとの一覧、達成済み（日付）・未達成（条件と進捗、例: 「回廊 50階（最高 38階）」）。隠し実績は、達成するまで「？？？」。
- **称号の選択**: ステータス画面に「称号」の欄を作り、獲得済みの称号から1つを選んで装備できる（回廊・図鑑・実績の称号を統合して一覧。表示のみで効果なし）。ステータス画面のキャラ名の近くに、装備中の称号を小さく表示する。
- 既存の称号の仕組み（`p.tower.title` / `p.tower.titles`）を壊さず、実績の称号も同じ仕組みに入れる（データ表を共通化してよい。既存の保存形式から読めること）。

#### 2-4. テスト
- `tools/test_p6b.py` を追加し、`README.md` に実行方法を書く。内容: 各カテゴリの実績が条件を満たしたときに1回だけ達成される、報酬（コイン・称号）の付与、本編クリア前のコインの保留と、クリア時の付与、隠し実績の表示、称号の装備、既存セーブの移行、画面（一覧・進捗・420px）。
- 既存テスト（`test_p1` 〜 `test_p6a`、`test_save_migration`）がすべて通る。本編周回・回廊・深淵のBOT結果が変わらない。ビルドが再現できる。

### 3. 守ること
- 作業は `dev`。1つのまとまり（2-1、2-2、2-3、2-4）ごとにコミット。実績の一覧と判定の仕様を `docs/dev_notes_P6b.md`（新規）に表で残す。
- 秘密情報（トークン・鍵）を、コード・コミット・ログ・報告に入れない。
- 仕様書と矛盾する判断が必要なときは、勝手に決めず、報告に「要確認」と書く。

### 4. 報告の形式
最後に次だけ、短く報告してください。
1. 2-1〜2-4 のそれぞれ（できた／できなかった）
2. 本編周回・回廊・深淵のBOT結果が変わっていないこと

4. 判定が重くないことの確認（判定の呼び出し頻度）
5. 仕様書と食い違った点・要確認の点
