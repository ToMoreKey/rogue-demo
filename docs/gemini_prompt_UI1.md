# Gemini 向け指示書: UI-1（ステータス画面の項目分け）

---

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で作業します。今回は UI-1「ステータス画面の項目分け」です。仕様と合格基準は `docs/change_UI1_status.md` に書いてあります（運営者承認済み）。

### 0. 前提（これまでと同じ）
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる。`src/assets/` は触らない。
- `window.__rogue` と `window.G` を残す。外部ライブラリを追加しない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄する）。既存コミットの書き換え・force push はしない。
- 画面の構造: ゲーム全体のスクロールは `#app` の中だけで行い、下のナビは画面下に固定されている（`src/css/main.css` の `#app`）。モーダルの下端ボタンは `.sheet>.act:last-child` の sticky で常に見える。これらを壊さない。

### 1. ゴール
ステータス画面（`renderStatus`）が、勇者・称号・極意・装備・バッグ・薬・強化石・外見変更・スキル・データを縦に全部並べていて探しにくい。画面上部に**サブタブ（ボタンの横一列）**を置き、選んだタブの項目だけを表示する。

### 2. やること
`docs/change_UI1_status.md` の 3〜5章をすべて実装する。要点:
1. タブは5つ: 勇者／装備／スキル／極意／データ。割り当ては 3章の表のとおり。既存のパネルは**中身・ボタンの動作を変えず**、どこか1つのタブに必ず入れる（欠落・重複なし）。スキル関連（`renderSkillSlots`・スキル枠など、`renderStatus` から呼ばれる別関数のパネル）も漏れなく割り当てる。
2. タブバーは、`#app` のスクロール領域の上端に sticky で付ける（背景は不透明）。選択中は色と下線で目立たせる。5つが 360px 幅でも1行に収まり、高さは40px以上。`role="tablist"`/`role="tab"`/`aria-selected`。
3. 選択状態は `G.statusTab`（メモリのみ。保存しない。初期値は勇者）。再描画で戻らない。タブを切り替えたらスクロールを一番上に戻す。
4. 未使用 SP があるとき「スキル」タブに点、クリア後で未使用 SP があるとき「極意」タブにも点を出す。「極意」タブは、クリア前は「本編クリアで解放されます」と表示する。
5. チュートリアルの SP 割り振り（step 41）・スキル装備（step 5）の手順では、自動で「スキル」タブに切り替える。図鑑・実績のモーダルを閉じたあとも元のタブに戻る。ほかの場所の「ステータス画面の○○で…」という案内文は、タブ名に合わせて直す。

### 3. 守ること（厳守）
- ゲームの数値・バランス・BOT結果、セーブ形式（v8）は変えない。新しい保存キーは作らない。
- 本番／テスト版ビルドの分離（`tools/build.py` の `to_dev`）を壊さない。
- 仕様と矛盾する判断は、勝手に決めず「要確認」と書く。
- `tools/test_ui1.py`（新規）を追加し、`README.md` に実行方法を書く。`docs/change_UI1_status.md` の7章（合格基準）の1〜6をすべてテストする（360・390・420px、全パネルがちょうど1タブに入ること、主要ボタンの動作、sticky、スクロールのリセット、再描画での保持、チュートリアル）。
- 全テスト（`test_p1`〜最新、`test_save_migration`、`test_variants`、`test_noskip`、`test_p8`、`test_p9`、`test_modal_close`、`test_layout`）が `RESULT: OK`。ビルドが再現できる（`cmp`）。本編・回廊・深淵のBOT結果が変わらない（本編: ラン数490〜510、`model_hours` 20.8〜21.2、Lv124。回廊・深淵は P7b 完了時点と同じ）。テストを通すために判定を弱めない（弱める場合は理由を報告に書く）。
- 実装メモを `docs/dev_notes_UI1.md`（新規）に残す。画面を 390×844 で撮ったスクリーンショットの確認結果（各タブ）も、文章で書く。
