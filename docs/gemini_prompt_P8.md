# Gemini 向け指示書: P8（セーブのバックアップ・引き継ぎ）

---

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で作業します。今回は P8「セーブのバックアップ・引き継ぎ」です。仕様と合格基準は `docs/change_P8_backup.md` に書いてあります（運営者承認済み）。

### 0. 前提（これまでと同じ）
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる。`src/assets/` は触らない。新しい `src/` ファイルを足したら `tools/build.py` の `JS_ORDER` に登録する。
- `window.__rogue` と `window.G` を残す。外部ライブラリを追加しない。外部への通信・送信は一切しない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄する）。既存コミットの書き換え・force push はしない。
- 本番ビルドとテスト版ビルド（`python3 tools/build.py <出力> --variant dev`）の分離を壊さない。新しい保存キー・IndexedDB名は、本番では本番用、テスト版では `rogue_dev_` 系に分ける（`tools/build.py` の `to_dev` に置換を追加し、`tools/test_variants.py` に確認を足す）。

### 1. ゴール
ブラウザのデータが消えてもセーブを守れるように、「書き出し・読み込み」と「消えにくくする仕組み」を追加する。

### 2. やること
`docs/change_P8_backup.md` の 2-1〜2-4 をすべて実装する。要点:
1. 設定画面に「セーブを書き出す」（ファイル／コード）と「セーブを読み込む」（ファイル／貼り付け）を追加する。初期化ボタンより目立たない位置にする。
2. 読み込みは、検証 → 確認画面（現在と書き出し側のレベル・ゴールド・進行を並べる）→ 現在のセーブを別キーに退避 → 置き換え → 既存の `migrations` で最新化 → 再描画。不正なものは何も変更せず理由を表示する。
3. `navigator.storage.persist()` の要求、IndexedDB への複製、起動時に localStorage が空で複製がある場合だけ「復元しますか？」を出す。勝手には復元しない。
4. 控えめな案内（トースト1回、7日に1回まで）。
5. ヘルプ画面に、バックアップの項目を1つ追加する（既存の文章は変えない）。

### 3. 守ること（厳守）
- ゲームの数値・バランス・BOT結果を変えない。セーブのバージョン（v8）と構造は変えない。書き出し日時など追加の記録は、セーブ本体ではなく別キーに置く。
- 仕様と矛盾する判断は、勝手に決めず「要確認」と書く。
- 秘密情報をコード・コミット・ログ・報告に入れない。
- `tools/test_p8.py`（新規）を追加し、`README.md` に実行方法を書く。`docs/change_P8_backup.md` の4章（合格基準）の1〜5をすべてテストする（ファイル・コード両方の往復一致、v1〜v7 の旧セーブ、壊れた入力、IndexedDBからの復元、初回プレイヤーに出ないこと、本番/テスト版のキー分離、420pxで横スクロールなし）。
- 全テスト（`test_p1`〜最新、`test_save_migration`、`test_variants`、`test_noskip`）が `RESULT: OK`。ビルドが再現できる（`cmp`）。本編・回廊・深淵のBOT結果が変わらない（本編: ラン数490〜510、`model_hours` 20.8〜21.2、Lv124。回廊・深淵は P7b 完了時点と同じ）。テストを通すために判定を弱めない（弱める場合は理由を報告に書く）。
- 実装メモを `docs/dev_notes_P8.md`（新規）に残す。

### 4. 報告の形式
最後に次だけ、短く報告してください。
1. 2-1〜2-4 とヘルプ追記の結果（できた／できなかった）
2. 合格基準1〜5の結果
3. テスト・ビルド・BOT結果
4. 要確認の点

### 5. 今回やらないこと
- クラウド保存・アカウント連携、数値調整、新機能、画像の生成・差し替え、APK化。
