# Gemini 向け指示書: R1a（キャラごとのスキル・パッシブ分け：仕組み）

## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」の開発担当エンジニアです。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）で、R1a「キャラごとのスキル・パッシブ分け（仕組み）」を実装します。仕様は `docs/change_R1_char_classes.md`（運営者承認済み）。**今回は R1 のうち §10「R1a の範囲」だけ**です（新規スキルの本格設計・演出・バランス調整は R1b/R1c で私が仕様化します）。

### 0. 前提
- `src/` を編集し `python3 tools/build.py` で生成。`index.html` は直接編集しない。`sw.js` の `CACHE` を上げる（CRLFを保つ）。`src/assets/` は触らない。`window.__rogue`/`window.G` を残す。外部ライブラリは追加しない。
- 作業は `dev`。`main` には push しない。push は従来どおり（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄）。既存コミットの書き換え・force push はしない。
- 関連コード: `src/data/skills.js`（`SKILL_TREES`、`SK`）、`src/js/20_state.js`（`passiveBonus`、`newPlayer`、`skillMpCost`）、`src/js/30_save.js`（セーブ・マイグレーション）、`src/js/50_acts.js`（`spAlloc`、スキル装備・リセット）、`src/js/60_render.js`（`renderStatus` のスキルタブ、キャラ変更UI）、`src/js/70_tutorial.js`、`src/assets/char_skins.js`（4キャラ: ruby/stella/silia/chloe）、`tools/bot.py`。

### 1. やること（`docs/change_R1_char_classes.md` の §1・§3・§4・§8・§9・§10）
1. **データモデル（セーブ v9）**: `p.chars[id] = { skillPts: {...}, equippedSkills: [..3] }`（id は ruby/stella/silia/chloe）。現キャラは既存の `p.skin`。SP（`p.sp`）は全キャラ共通。`p.passiveSkills` と `p.equippedSkills` は、現キャラの値を指す（切替時に入れ替える、または都度計算する）形にし、**既存の `passiveBonus`、`skillMpCost`、戦闘ロジック、塔・深淵の計算はなるべく変えない**。
2. **マイグレーション v8→v9**: 全SPを返却（`p.sp` に加算。すべてのツリーの `skillPts` 合計＋進化枠の分を含む）、習得スキル・スロット・パッシブをリセットし、各キャラの空の `chars` を作る。「システムが変わりました。SPを全て返却したので、キャラごとに振り直してください」の案内を1回だけ表示する。v8のバックアップ（既存の `_bak_v8`）は残す。`test_save_migration.py` に v8→v9 を追加。
3. **ツリー定義**: キャラごとのツリー一覧（主・第2・奥義の3つ、各30SP、解放条件は主10/主20かつ第2が20）を **1ファイルのデータ**（例 `src/data/char_trees.js`）にまとめる。暫定割り当て（`// TODO(R1b)` と明記）:
   - ステラ: 剣枠・戦士枠・英雄枠（現在のまま）
   - ルビィ: 魔法枠・魔術師枠・英雄枠のコピー（暫定）
   - シリア: 生命枠・詠唱枠・英雄枠のコピー（暫定）
   - クロエ: 剣枠のコピー（暫定）・戦士枠のコピー・英雄枠のコピー。最初の3SPのスキルは「ダブルスタブ」（2回攻撃、各1.1倍、MP7、CT2）を新規に追加。
   - 非ヒーラー（ステラ・ルビィ・クロエ）の主ツリーの10SP付近に、新スキル「応急手当」（回復20%、MP12、CT5、`type:'heal'`）を追加（既存スキルと入れ替えるか、枠を詰める）。ヒール・リジェネ・フルヒールはシリアの生命枠だけ。
   - 同じスキルIDが複数キャラにある場合の扱い（共通ID、キャラごとの習得管理）を決め、`docs/dev_notes_R1a.md` に書く。
4. **UI**: ステータス「スキル」タブは現キャラのツリーだけを表示。キャラ変更UI（勇者タブの外見変更を「キャラ変更」に統合）。変更時、**ダンジョン攻略中は押せない**。キャラ別のスロット切替。キャラカード＋説明文（§8.1の説明文を整えて使う）。
5. **キャラ選択モーダル（新規ゲームの最初）**: §8.1のとおり。選ぶまで閉じられない。カードを押すと説明（特徴・できること・おすすめ・弱み）を表示、「このキャラで始める」で確定。既存プレイヤー（チュートリアル済み）には出さない。選択後、チュートリアル step 0（ダンジョンタブを押す）へ。
6. **チュートリアル**: step 41/5 のスキルを、現キャラの最初の3SPのスキル（ステラ=強撃、ルビィ=ファイアボール、シリア=ヒール、クロエ=ダブルスタブ）に差し替える。ツリーID・スキルID・文言をデータから引く（`life`/`heal` のハードコードをやめる）。流れは変えない。
7. **BOT（`tools/bot.py`）**: キャラ引数（`--char stella|ruby|silia|chloe`、既定 stella）を追加し、現キャラのツリーを使って SP を振る・スキルを装備するように直す。R1aでは数値の合格は求めない（動いて結果が出ること）。既定（stella）の本編結果が、今のBOT基準に近いか（参考値として）報告する。

### 2. 守ること（厳守）
- 戦闘・ダメージ計算・演出（Q1〜Q3）・塔・深淵・ランキング・極意・図鑑・実績・利用状況送信（P10）・不具合報告（P9）を壊さない。`to_dev` の分離（保存キーなど）を維持。
- v8→v9 の移行で、**SPが失われない**（返却合計＝移行前の消費SP＋残SP）。テストで確認する。
- 仕様と矛盾する判断は勝手に決めず「要確認」と書く。
