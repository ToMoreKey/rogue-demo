# 変更書: P10（匿名の利用状況の送信）

## 1. 目的
どれぐらいのユーザーが、どこまで、どれぐらい遊んでいるかを知る。GitHub Pages にはアクセスログがないため、ゲームから匿名の記録をGoogleフォーム（不具合報告と同じ方式）へ送る。運営者承認済み（2026-11-24、案A）。

## 2. 送る内容（個人を特定する情報は送らない）
1行（1回の送信）に次の項目だけ。
`id`（匿名ID）、`ver`（APP_VERSION）、`lv`、`dg`（最高到達ダンジョン）、`clear`（本編クリア済み 0/1）、`tw`（塔の最高階）、`ab`（深淵の最高到達）、`hours`（累計プレイ時間・時間、小数1桁）、`launch`（累計起動回数）、`vp`（画面サイズ）、`new`（この端末の初回送信なら1）
- 診断情報と同じ形式の1行文字列（`k=v; k=v`）にして、フォームの1つの質問（記録）に入れる。名前・メール・セーブデータの内容・不具合報告の本文は送らない。
- 匿名IDは初回起動時に乱数（`crypto.getRandomValues`、無ければ `Math.random`）で16文字を作り、`localStorage` の新キー `rogue_anon_id_v1` に保存。セーブデータ（v8）には入れない（書き出し・読み込みで他人にIDが移らないようにする）。

## 3. 送信のタイミング
- 起動時、前回の送信から24時間以上経っていれば1回送る（送信時刻を `rogue_stats_last_v1` に保存）。失敗しても本編を止めない（サイレント）。オフラインならスキップ（キューに溜めない）。
- 累計プレイ時間と起動回数は、既存のセーブ項目を使う。無ければ、起動回数 `rogue_stats_launch_v1` を新設して数える（既存の統計があればそれを優先し、勝手にセーブ形式を変えない）。
- 本番ビルドのみ送信。テスト版（dev）は送信しない（`to_dev` で設定を空にする。キー名は `to_dev` で分離）。URLが空なら何もしない。

## 4. ユーザーへの告知とオフ
- 「データ」タブに「匿名の利用状況を送信する」のスイッチ（初期オン）と、1〜2行の説明（何を送るか・個人情報は送らない）を置く。オフにしたら送らない（`rogue_stats_optout_v1`）。
- ヘルプの「はじめに」タブの末尾にも、同じ説明を1行入れる。

## 5. 設定とツール
- `src/data/analytics.js`（`ANALYTICS_CFG`: `reportUrl`、`entryStats`、`intervalHours:24`、各キー名）。URLと entry ID は空で出荷し、運営者がフォーム作成後に docs の手順で入れる。
- `tools/make_stats.py`（新規）: スプレッドシートのCSV（1列目=タイムスタンプ、2列目=記録）から集計して `docs/stats_report.md` を作る。
  - 総ユーザー数（匿名ID数）、日別アクティブ数（直近30日）、新規ユーザー数の推移、バージョン別、Lv帯別分布、最高到達ダンジョン別の人数、クリア率、1人あたりの累計プレイ時間（中央値・平均）、起動回数、離脱の目安（最終送信が7日以上前）。標準ライブラリのみ。
  - 同一IDの複数行は最新の行を「現在値」、初出日を「開始日」として扱う。
- `docs/analytics_setup.md`（フォームの作り方・設定値の入れ方・スプレッドシートからのCSV書き出し・集計の実行。私が書く）。

## 6. 守ること
数値・バランス・BOT・セーブ形式(v8)は変えない。`to_dev` で dev は送信しない。トークン等は入れない（フォームURLとentry IDは公開情報でよい）。外部ライブラリを追加しない。

## 7. 合格基準
1. URLが空なら通信が一切起きない。devビルドでも通信しない。
2. 本番設定のとき、起動時に1回だけ送信される（24時間以内の再起動では送らない）。送る文字列に個人情報・セーブ内容が含まれない（テストで、送信ボディをモックして確認）。
3. オプトアウトで送信が止まる。スイッチが「データ」タブに表示され、状態が保持される。
4. 匿名IDが端末内で固定、セーブの書き出し・読み込みでIDが変わらない・移らない。
5. 送信失敗・オフラインでゲームが止まらず、ページエラーが出ない。
6. `tools/make_stats.py` が、サンプルCSV（テストで作る）から正しく集計する。
7. 全テストOK、ビルド再現、BOT結果不変。
