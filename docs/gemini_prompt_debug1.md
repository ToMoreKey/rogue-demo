## 【プロンプト本文（ここから貼り付け）】

あなたは、ブラウザで動くローグライクRPG「rogue-demo」のデバッグ担当です。リポジトリ `ToMoreKey/rogue-demo` の `dev` ブランチ（最新を取得してから）を対象にします。今回は**不具合の洗い出しと、明らかな不具合の修正だけ**を行います。

### 0. 前提
- `src/` を編集し、`python3 tools/build.py` で `index.html` を生成する。`index.html` は直接編集しない。修正した場合は `sw.js` の `CACHE` を上げる。`src/assets/` は触らない。
- 作業は `dev` ブランチ。`main` には push しない。push はこれまでと同じ方法（トークンは設定ファイルから読み、その場の変数で使い、画面・ログ・ファイル・コミット・報告に出さず、使い終わったら破棄する）。既存コミットの書き換え・force push はしない。
- **数値バランスは変えない**（敵・装備・スキル・ドロップ・コイン等の数値、BOT結果）。バランスの気づきは報告に書くだけにする（P7で扱う）。
- 新機能・UI変更・画像の差し替えはしない。セーブ形式を変える修正が必要なら、勝手に直さず「要確認」と報告する。

### 1. 調べること（Playwright と `window.__rogue` を使う）
1. **進行不能**: 新規セーブから、A〜O の全ダンジョン（各難度）を順に解放・クリアでき、本編クリア → 回廊 → 深淵の解放まで進められるか（`startRun`/`tick` の自動進行でよい）。詰む状態（ボタンが押せない、モーダルが閉じられない、次の画面に行けない）がないか。
2. **例外**: 全画面（街・ダンジョン選択・戦闘・ステータス・装備・強化・スキル・極意・図鑑・実績・称号・ヘルプ・回廊・深淵・ランキング・設定）を巡回し、`pageerror` とコンソールエラーが 0 か。
3. **数値の異常**: NaN・undefined・負の値・Infinity が、HP・ATK・DEF・ゴールド・EXP・SP・コイン・ドロップ率・表示テキストに出ないか（戦闘 1,000 ティック以上を、複数ダンジョン・複数ビルドで）。
4. **セーブ**: 保存 → 再読み込みで状態が一致するか。旧セーブ（`rogue_test_save_v1_bak_vN` や `test_save_migration.py` の各バージョン）から最新へ移行して壊れないか。壊れたセーブ（不正JSON・欠けたフィールド）で起動が落ちないか。
5. **装備・強化・特性**: ★1〜9 の装備、強化、特性（武器0〜3・防具0〜2）、神話装備、装備の付け外し・売却・ロックで、状態が不整合にならないか（所持数の増減、二重装備、存在しないIDの参照）。
6. **回廊・深淵**: 祝福の選択（3択・2択）、コインの増減と交換、称号の購入・装備、深淵の難度選択・呪いの累積・敗北時の扱いに矛盾がないか。
7. **図鑑・実績・お知らせ**: 条件を満たしたときだけ記録・解放されるか。クリア後のお知らせが1回だけ出るか。
8. **画面**: 420px と 360px 幅で、主要画面に横スクロールや文字のはみ出しがないか（スクリーンショットで確認）。
9. **オフライン**: Service Worker 登録後にオフラインにして、起動・戦闘・街が動くか。

### 2. 修正の方針
- 原因が明らかで、数値・仕様に関わらない不具合だけを修正する。1件ごとに別コミット（メッセージに不具合の内容を書く）。
- 修正ごとに、再発を防ぐテストを `tools/test_debug1.py`（新規）に足す。`README.md` に実行方法を書く。
- 迷うもの（仕様か不具合か判断できない、数値に関わる、セーブ形式に関わる）は修正せず、「要確認」として報告する。

### 3. 守ること（厳守）
- 全テスト（`test_p1` 〜 最新、`test_save_migration`、`test_debug1`）が `RESULT: OK`。ビルドが再現できる（`cmp`）。
- 本編周回・回廊・深淵のBOT結果が変わらない（本編: ラン数490〜493、`model_hours` 20.85〜20.94、1階あたりティック4.06〜4.13、Lv124。回廊: 最適59/64/69、ランダム51/53/59。深淵: 標準 d1〜3 が100%・d6〜10 が0%、強化 d10 は0〜20%）。結果をそのまま報告に載せる。
- 秘密情報をコード・コミット・ログ・報告に入れない。
- 調査内容と結果は `docs/dev_notes_debug1.md`（新規）に残す（確認した項目、見つけた不具合、修正したもの、要確認のもの）。

最後に次だけ、短く報告してください。
