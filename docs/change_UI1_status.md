# 変更書: UI-1（ステータス画面の項目分け）

## 1. 背景
ステータス画面に、勇者・称号・極意・装備・バッグ・薬・強化石・外見変更・スキル・データが縦に全部並んでいて、目的の項目を探すのに時間がかかる。運営者の要望（2026-11-24）: 項目を分類し、ボタンを横一列に並べて切り替えられるようにする。

## 2. 方針
ステータス画面の上部に、**サブタブ（ボタンの横一列）**を置く。選んだタブの項目だけを表示する。下のナビ（街・ダンジョン・ステータス・ヘルプ）とは別物で、ステータス画面の中の切り替え。

## 3. タブの分け方（5つ。1行に収める）
| タブ | 中身（既存のパネルをそのまま移す） |
|---|---|
| 勇者 | 勇者（立ち絵・ステータス・図鑑／実績ボタン）、称号、外見変更 |
| 装備 | 装備、バッグ、薬、強化石 |
| スキル | スキルセット（装備スキル）、スキル枠（SP割り振り・進化枠） |
| 極意 | 極意（共通パッシブ）。クリア前は、タブは出すが中身に「本編クリアで解放されます」と表示する |
| データ | データ（保存・書き出し／読み込み・不具合報告・初期化・テスト用ボタン） |

- すべての既存パネルが、**どこか1つのタブに必ず入る**（欠落・重複なし）。中身の内容・ボタンの動作は変えない。
- 各パネルの内部の作りは変えない。パネルを包む表示切り替えと、タブバーだけを足す。

## 4. 動作
- タブバーは、ステータス画面の一番上。`position: sticky; top: 0`（`#app` のスクロール領域の上端に付く）で、スクロールしても見える。背景は不透明にして、下の内容が透けない。
- 選択中のタブは、色と下線で目立たせる（既存のボタンの `on` と同じ見た目の流儀）。
- 選択状態は `G.statusTab`（保存しない。初期値は「勇者」）。ほかの画面に行って戻っても、同じセッション中は保持する。
- タブを切り替えたら、スクロール位置を一番上に戻す。
- ゲームの再描画（戦闘中の自動更新など）で、選択タブが戻らない・ちらつかない。
- **通知の点（任意だが推奨）**: 未使用の SP があるとき、「スキル」タブに小さな点を出す。クリア後で未使用の SP があるとき、「極意」タブにも点を出す。
- ラベルは短く（3〜4文字）、360px 幅でも5つが1行に収まり、はみ出さない。タップしやすい高さ（40px 以上）。
- アクセシビリティ: `role="tablist"` / `role="tab"` / `aria-selected`。

## 5. 他の機能との連動（必ず確認）
- **チュートリアル**（`src/js/70_tutorial.js`）: SP割り振り（step 41）とスキル装備（step 5）は、ステータス画面の「スキル」タブ内の要素を指す。チュートリアル中は、該当の手順で自動的に「スキル」タブに切り替える。`test_noskip.py` が引き続き通ること。
- 図鑑・実績のモーダルの開閉後も、元のタブに戻る。
- 他の場所からステータス画面へ移動する処理（実績の通知、ヘルプの案内文など）で、特定の項目を前提にした文言があれば、タブ名に合わせて直す（例: 「ステータス画面のスキルセットで…」→「ステータス画面の『スキル』タブで…」）。
- セーブの書き出し・読み込み、不具合報告の入口（データパネル）は、「データ」タブに入る。

## 6. 守ること
- ゲームの数値・バランス・BOT結果、セーブ形式（v8）は変えない。
- 新しい保存キーは作らない（`G.statusTab` はメモリのみ）。
- 本番／テスト版の分離（`to_dev`）を壊さない。外部ライブラリを追加しない。

## 7. 合格基準
1. 5つのタブが、360px・390px・420px で1行に収まり、横スクロールが出ない。タブの高さが40px以上。
2. 各タブで、割り当てた項目だけが表示される。以前のすべてのパネル（勇者・称号・極意・装備・バッグ・薬・強化石・外見変更・スキルセット・スキル枠・データ）が、ちょうど1つのタブに入る（テストで、全タブの見出しを集めて確認する）。
3. 各パネルのボタンの動作が、以前と同じ（装備の付け外し、SP割り振り、極意の強化、薬の使用、外見変更、書き出し、不具合報告など。主要なものをテストする）。
4. スクロールしてもタブバーが上端に残る。タブ切り替えでスクロール位置が上に戻る。
5. 戦闘中・再描画で選択タブが変わらない。他の画面から戻っても保持される。
6. チュートリアルが最後まで進められる（`test_noskip.py`）。SP割り振り・スキル装備の手順で「スキル」タブに自動で切り替わる。
7. 全テストが OK、ビルド再現、BOT結果が変わらない。
